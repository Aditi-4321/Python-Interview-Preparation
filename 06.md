## Question 6 — What is the difference between mutable and immutable objects?

### Answer

The difference is based on whether an **object can be changed after it has been created**.

* **Mutable object** → its internal state/content can be changed after creation.
* **Immutable object** → its state/content cannot be changed after creation.

This distinction is important in Python because it affects **assignment, function arguments, copying, object sharing, and program behavior**.

---

## 1. Mutable Objects

A **mutable object** can be modified after it is created without creating a completely new object.

Common mutable built-in types include:

```text
list
dict
set
bytearray
```

### Example

```python
numbers = [10, 20, 30]

numbers.append(40)

print(numbers)
```

Output:

```text
[10, 20, 30, 40]
```

The list object itself was modified.

Conceptually:

```text
Before:

numbers ───► [10, 20, 30]

After:

numbers ───► [10, 20, 30, 40]
```

The same list object can be changed.

---

## 2. Immutable Objects

An **immutable object cannot be modified after it has been created**.

Common immutable built-in types include:

```text
int
float
complex
bool
str
tuple
range
bytes
frozenset
```

For example:

```python
x = 10
x = x + 5

print(x)
```

It may look like the value `10` was changed to `15`, but that is not what happened.

Conceptually:

```text
Initially:

x ───► 10

After x = x + 5:

x ───► 15
```

A new integer object representing `15` is used, and the name `x` is rebound to it. The original integer object `10` was not modified.

---

## Mutable vs Immutable

| Feature                                         | Mutable               | Immutable                     |
| ----------------------------------------------- | --------------------- | ----------------------------- |
| Can object be modified after creation?          | Yes                   | No                            |
| Modification changes existing object?           | Generally yes         | No                            |
| Common examples                                 | `list`, `dict`, `set` | `int`, `str`, `tuple`, `bool` |
| Can be shared safely without mutation concerns? | Requires care         | Generally easier              |
| Can be used as a dictionary key?                | Usually no            | Some immutable objects can    |

The last row needs an important qualification: **being immutable alone is not sufficient for an object to be hashable**. Dictionary keys and set elements must be hashable.

---

## 3. Why Does This Matter?

Consider:

```python
a = [1, 2, 3]
b = a

b.append(4)

print(a)
```

Output:

```text
[1, 2, 3, 4]
```

Why?

Because both names refer to the **same mutable list object**:

```text
a ─────┐
       ├──► [1, 2, 3, 4]
b ─────┘
```

Changing the object through `b` is therefore visible through `a`.

---

### Compare with an Immutable Object

```python
a = 10
b = a

b = b + 5

print(a)
print(b)
```

Output:

```text
10
15
```

Here, `b = b + 5` does not modify the integer object `10`.

Instead:

```text
Before:

a ─────┐
       ├──► 10
b ─────┘

After:

a ───────► 10

b ───────► 15
```

The name `b` is rebound to another integer object.

---

## 4. Strings Are Immutable

This is a common interview example.

```python
name = "Python"

# name[0] = "J"
```

This produces a `TypeError` because individual characters of a string cannot be modified.

Instead, create a new string:

```python
name = "J" + name[1:]

print(name)
```

Output:

```text
Jython
```

The original string was not modified.

---

## 5. Tuples Are Immutable — But Their Contents Can Be Mutable

This is an important interview nuance.

Consider:

```python
data = ([1, 2], 10)

data[0].append(3)

print(data)
```

Output:

```text
([1, 2, 3], 10)
```

The tuple itself is immutable: you cannot replace its first element.

But the first element is a **mutable list**, and that list can be modified.

For example:

```python
# data[0] = [5, 6]   # TypeError
```

So, when discussing immutability, always consider **what exactly is immutable**.

## 6. Mutable and Immutable Objects as Function Arguments

Consider:

```python
def add_item(items):
    items.append(100)

numbers = [1, 2, 3]

add_item(numbers)

print(numbers)
```

Output:

```text
[1, 2, 3, 100]
```

The function received a reference to the same list object and modified it.

Now consider an integer:

```python
def change_number(number):
    number = number + 100

x = 10

change_number(x)

print(x)
```

Output:

```text
10
```

The function's local name `number` was rebound to another integer object. The caller's `x` was not changed.

### Important

Python uses **call-by-sharing / object-reference semantics**. Arguments are passed as object references; whether the caller observes a change depends largely on whether the referenced object is mutated or the local name is merely rebound.

---

## 7. Why Are Immutable Objects Useful?

Immutability can make objects easier to reason about because their state cannot unexpectedly change after creation.

It is particularly useful when:

* Values should remain fixed
* Objects are shared between different parts of a program
* Hashable objects are required as dictionary keys or set elements
* You want to avoid accidental mutation

For example:

```python
student_id = 723045
```

An integer's value cannot be modified in place.

---

## Common Mistakes

### Mistake 1: "Immutable means the variable cannot change."

Incorrect.

```python
x = 10
x = 20
```

The **name** `x` changed what object it refers to. The integer object `10` itself was not modified.

### Mistake 2: "Assignment always creates a copy."

Incorrect.

```python
a = [1, 2]
b = a
```

Both names refer to the same list.

### Mistake 3: "All tuples are completely immutable internally."

A tuple cannot change its own elements, but it can contain mutable objects whose state can change.

### Mistake 4: "All immutable objects can be dictionary keys."

Not necessarily. An object must be **hashable** to be used as a dictionary key or set element.

---

## Practical Example

In an ML project, suppose you have:

```python
features = [10, 20, 30]
backup = features
```

If you modify:

```python
features.append(40)
```

then `backup` also sees the change because both names refer to the same list.

If you need an independent list:

```python
backup = features.copy()
```

Now modifying `features` does not modify the top-level list structure of `backup`.

This distinction becomes important when preprocessing data, maintaining backups, or passing collections between functions.

---

## Interview Takeaway

Remember:

> **Mutable objects can be changed after creation, while immutable objects cannot. Lists, dictionaries, and sets are common mutable types, whereas integers, strings, tuples, and bytes are common immutable types. Assignment does not automatically create a copy; multiple names can refer to the same mutable object.**

The key interview concept is:

```text
Mutable:
name ───► object
            ↓
       object can change

Immutable:
name ───► object
            ↓
       object cannot change
       name can be rebound
```
