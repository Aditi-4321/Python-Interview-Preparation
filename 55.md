# Question 55 — What are closures and how are they related to decorators?

## Answer

### 1. What is a Closure?

A **closure** is a function that **remembers and can access variables from its enclosing (outer) function even after the outer function has finished executing**.

In simple words:

> **Closure = Inner function + remembered variables from the outer function**

Closures are possible because functions in Python are **first-class objects** and can remember their enclosing scope.

### 2. Basic Example

```python
def outer(x):
    def inner(y):
        return x + y

    return inner


add_10 = outer(10)

print(add_10(5))
```

Output:

```text
15
```

Here:

* `outer(10)` creates the variable `x = 10`.
* `inner()` uses `x`.
* `outer()` returns `inner`.
* Even though `outer()` has finished execution, `inner()` still remembers `x = 10`.
* Therefore, `add_10(5)` returns `15`.

The variable `x` is part of the closure.

---

## 3. Why Does a Closure Work?

Consider:

```python
def outer(x):
    def inner(y):
        return x + y
    return inner
```

The scope relationship is:

```text
outer()
 └── x
     │
     └── inner()
          │
          └── remembers x
```

The inner function has access to the enclosing function's variables according to Python's **LEGB scope rule**.

When the inner function is returned, Python keeps the necessary referenced values available through the function's closure.

You can inspect this using:

```python
print(add_10.__closure__)
```

and:

```python
print(add_10.__closure__[0].cell_contents)
```

which can show:

```text
10
```

---

## 4. Closure with `nonlocal`

A closure can also modify a variable from its enclosing scope using `nonlocal`.

```python
def counter():
    count = 0

    def increment():
        nonlocal count
        count += 1
        return count

    return increment


c = counter()

print(c())  # 1
print(c())  # 2
print(c())  # 3
```

Here, `count` is preserved between calls.

This makes closures useful for maintaining **private state** without using a global variable or a class.

# 5. How Are Closures Related to Decorators?

Closures are one of the most common mechanisms used to **implement decorators**.

A decorator usually contains:

1. An outer function that receives another function.
2. An inner wrapper function.
3. The wrapper accesses the original function from the enclosing scope.
4. The outer function returns the wrapper.

Example:

```python
def my_decorator(func):

    def wrapper():
        print("Before function")
        func()
        print("After function")

    return wrapper


@my_decorator
def greet():
    print("Hello")


greet()
```

Output:

```text
Before function
Hello
After function
```

The important part is:

```python
def my_decorator(func):

    def wrapper():
        func()

    return wrapper
```

Here, `wrapper()` remembers the `func` variable from `my_decorator()`.

Therefore, `wrapper` is a **closure**.

---

## 6. Decorator Relationship

A useful way to remember the relationship is:

```text
Closure
   ↓
Inner function remembers outer variables
   ↓
Can preserve state / access enclosed objects
   ↓
Useful mechanism for implementing decorators
```

A decorator itself is **not the same thing as a closure**.

* **Closure** is a function behavior/scope mechanism.
* **Decorator** is a design pattern/technique for modifying or extending the behavior of another function or class.

A decorator **can be implemented using a closure**, and the wrapper function in a typical decorator is usually a closure.

---

## 7. Real Decorator Example

Suppose we want to measure execution time:

```python
import time
from functools import wraps


def timer(func):

    @wraps(func)
    def wrapper(*args, **kwargs):
        start = time.time()

        result = func(*args, **kwargs)

        end = time.time()
        print("Time:", end - start)

        return result

    return wrapper


@timer
def calculate():
    total = sum(range(1000000))
    return total


calculate()
```

Here:

* `timer()` is the decorator.
* `wrapper()` is the inner function.
* `func` is captured by `wrapper`.
* Therefore, `wrapper` forms a closure.
* `@timer` replaces `calculate` with the decorated wrapper.

Conceptually:

```python
calculate = timer(calculate)
```

So the relationship is:

```text
Decorator
   │
   ├── receives original function
   │
   ├── creates wrapper function
   │
   └── returns wrapper
              │
              └── wrapper remembers original function
                  through a closure
```

## 8. Why Are Closures Useful?

Closures are useful when you want a function to:

* Remember state between calls.
* Keep data private from the outside.
* Create customized functions.
* Avoid unnecessary global variables.
* Implement decorators.
* Build function factories and callbacks.

For example:

```python
def multiplier(n):
    def multiply(x):
        return x * n

    return multiply


double = multiplier(2)
triple = multiplier(3)

print(double(5))   # 10
print(triple(5))   # 15
```

Both functions remember different values of `n`.

## 9. Closure vs Class for Maintaining State

A closure can sometimes provide a simpler alternative to a small stateful class.

### Closure

```python
def counter():
    count = 0

    def increment():
        nonlocal count
        count += 1
        return count

    return increment
```

### Class

```python
class Counter:
    def __init__(self):
        self.count = 0

    def increment(self):
        self.count += 1
        return self.count
```

Both can maintain state.

A closure is often convenient for **small, localized state**, while a class can be clearer when the state and behavior become more complex or multiple methods are required.

## 10. Common Mistakes

### Mistake 1: Thinking every nested function is a closure

A nested function becomes relevant as a closure when it **references variables from its enclosing scope** and retains access to them.

### Mistake 2: Confusing closure with decorator

They are related but not identical.

> **Closure is a mechanism; decorator is a technique/pattern.**

### Mistake 3: Forgetting `nonlocal`

If you want to modify an enclosing variable:

```python
def counter():
    count = 0

    def increment():
        nonlocal count
        count += 1
```

Without `nonlocal`, `count += 1` would be treated as an assignment to a local variable inside `increment()`.

## 11. ML/AI Relevance

Closures and decorators are useful in ML applications for implementing reusable behavior such as:

* Logging
* Execution-time measurement
* Input validation
* Authentication/authorization in ML APIs
* Monitoring
* Caching
* Retry mechanisms
* Preprocessing wrappers

For example, a decorator could log when an ML model's prediction function is called without changing the prediction logic itself.

## Interview Takeaway

> **A closure is a function that retains access to variables from its enclosing scope even after the enclosing function has finished executing. Decorators commonly use closures because their wrapper function needs to remember the original function and optionally other configuration values.**

### Interview Follow-up

**Q: Is every decorator a closure?**
Not necessarily. A decorator can be implemented in different ways, including using a callable class. However, function-based decorators commonly use closures.

**Q: What is the difference between a closure and a decorator?**
A closure is a scope/function mechanism that retains enclosed variables, whereas a decorator is a technique for extending or modifying the behavior of another function or class.

**Q: What is the role of `functools.wraps` in decorators?**
It preserves metadata such as the original function's name and docstring when the wrapper replaces the original function.
