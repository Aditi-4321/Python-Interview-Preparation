# Question 54 — What is a decorator?

## Answer

A **decorator** in Python is a function that **modifies or extends the behavior of another function or class without changing its original source code**.

Decorators are based on the fact that Python functions are **first-class objects**: they can be passed as arguments, returned from other functions, and assigned to variables.

### Simple definition

> **A decorator is a callable that takes another function or class, adds or changes behavior, and returns a modified callable.**

---

## 1. Basic Example

Suppose we have:

```python id="p2b7f4"
def greet():
    print("Hello!")
```

We want to print a message before calling `greet()`.

We could modify the function directly, but a decorator lets us add this behavior separately.

```python id="h4n8sx"
def my_decorator(func):

    def wrapper():
        print("Before function")
        func()
        print("After function")

    return wrapper
```

Apply it:

```python id="v9x3kq"
@my_decorator
def greet():
    print("Hello!")


greet()
```

Output:

```text id="a7m2cp"
Before function
Hello!
After function
```

---

## 2. What Does `@my_decorator` Mean?

This:

```python id="x8v5nc"
@my_decorator
def greet():
    print("Hello!")
```

is essentially equivalent to:

```python id="q4r6tz"
def greet():
    print("Hello!")

greet = my_decorator(greet)
```

So the decorator receives the original `greet` function and returns the new `wrapper` function.

```text id="0s7c4e"
Original function
      ↓
my_decorator()
      ↓
Modified/wrapped function
```

---

## 3. Why Use Decorators?

Decorators are useful when the same additional behavior needs to be applied to multiple functions.

Common examples include:

* Logging
* Timing functions
* Authentication/authorization
* Input validation
* Caching
* Access control
* Retry logic
* Monitoring
* Transaction management

Instead of duplicating the same code in every function, we can define it once in a decorator.

---

## 4. Decorator with Function Arguments

The previous example only works with a function that takes no arguments.

For general-purpose decorators, use `*args` and `**kwargs`.

```python id="2j4m8c"
def my_decorator(func):

    def wrapper(*args, **kwargs):
        print("Function is starting")
        result = func(*args, **kwargs)
        print("Function is finished")
        return result

    return wrapper
```

Now it can work with different functions:

```python id="6x1q9b"
@my_decorator
def add(a, b):
    return a + b


result = add(10, 20)

print(result)
```

Output:

```text id="v6m4zs"
Function is starting
Function is finished
30
```

The `*args` collects positional arguments and `**kwargs` collects keyword arguments.

---

## 5. Preserving Function Metadata with `functools.wraps`

A decorator replaces the original function with the wrapper. Without additional handling, information such as the function's name and docstring can be changed.

For example:

```python id="4g5s2d"
def my_decorator(func):
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)

    return wrapper
```

A better practice is to use `functools.wraps`:

```python id="9q3v7m"
from functools import wraps


def my_decorator(func):

    @wraps(func)
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)

    return wrapper
```

`@wraps(func)` preserves important metadata such as:

* `__name__`
* `__doc__`
* Other function metadata

This is recommended when writing reusable decorators.

## 6. Practical Example: Timing a Function

Decorators are commonly used for performance monitoring.

```python id="k8m4w2"
import time
from functools import wraps


def timer(func):

    @wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()

        result = func(*args, **kwargs)

        end = time.perf_counter()

        print("Time:", end - start, "seconds")

        return result

    return wrapper
```

Use it:

```python id="c7n2px"
@timer
def calculate():
    total = sum(range(1_000_000))
    return total


calculate()
```

The decorator adds timing behavior without modifying `calculate()` itself.

This can be useful when profiling or monitoring ML preprocessing and inference functions.

---

## 7. Practical Example: Logging

```python id="w6k1az"
from functools import wraps


def log_call(func):

    @wraps(func)
    def wrapper(*args, **kwargs):
        print(f"Calling {func.__name__}")
        result = func(*args, **kwargs)
        print(f"Finished {func.__name__}")
        return result

    return wrapper


@log_call
def predict(model, data):
    return model.predict(data)
```

The prediction function remains focused on prediction, while logging is handled separately.

This is an example of **separation of concerns**.

## 8. Decorators in Web and ML Applications

Decorators are widely used in real Python frameworks.

For example, web frameworks may use decorators for:

```python
@app.route("/users")
def users():
    ...
```

A framework can use the decorator to register the function as a handler for a particular route.

Decorators can also be used for:

* Authentication
* API authorization
* Request validation
* Rate limiting
* Logging
* Caching
* Monitoring model inference

The exact decorators depend on the framework being used.

---

## 9. Multiple Decorators

A function can have multiple decorators:

```python id="q3v8mn"
@decorator1
@decorator2
def function():
    pass
```

This is conceptually equivalent to:

```python id="j7r5kx"
function = decorator1(decorator2(function))
```

Therefore, decorator order matters.

The decorator closest to the function is applied first.

---

## 10. Decorators vs Functions

A normal function performs some operation:

```python id="b5x8qk"
def add(a, b):
    return a + b
```

A decorator **wraps another callable to add reusable behavior**:

```python id="n4m6tw"
@timer
def add(a, b):
    return a + b
```

The original business logic remains mostly unchanged.

## Common Mistakes

### 1. Forgetting to return the wrapper

```python
def decorator(func):
    def wrapper():
        func()
```

This decorator doesn't return `wrapper`, so the decorated function becomes `None`.

Correct:

```python
def decorator(func):
    def wrapper():
        func()

    return wrapper
```

### 2. Forgetting `*args` and `**kwargs`

A decorator intended for general functions should usually accept and forward arbitrary arguments:

```python
def wrapper(*args, **kwargs):
    return func(*args, **kwargs)
```

### 3. Forgetting `functools.wraps`

For reusable decorators, `@wraps(func)` helps preserve the wrapped function's metadata and makes debugging/introspection easier.

### 4. Confusing a decorator with a decorator function

The `@decorator` syntax is simply convenient syntax for applying a callable that receives and returns a callable.

---

## Interview Takeaway

> **A decorator is a callable that takes another function or class and returns a modified version, allowing behavior such as logging, timing, validation, caching, or authorization to be added without changing the original code.**

### Easy Mental Model

```text id="c2m7vx"
Original Function
       ↓
   Decorator
       ↓
Wrapped Function
       ↓
Extra Behavior + Original Behavior
```

**Most important interview points:**

* Decorators rely on Python's first-class functions.
* `@decorator` is syntactic sugar for `function = decorator(function)`.
* Use `*args` and `**kwargs` for flexible wrappers.
* Use `functools.wraps` in well-designed decorators.
* Decorators promote **code reuse and separation of concerns**.
