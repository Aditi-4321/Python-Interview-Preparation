# Question 45 — Explain try, except, else, and finally.

## Answer

Python provides `try`, `except`, `else`, and `finally` blocks for **exception handling**. They allow a program to handle unexpected runtime situations without abruptly terminating.

The basic structure is:

```python
try:
    # Code that may raise an exception
except SomeException:
    # Handle the exception
else:
    # Runs if no exception occurred
finally:
    # Runs whether an exception occurred or not
```

---

## 1. `try`

The `try` block contains code that **may raise an exception**.

```python
try:
    result = 10 / 2
```

If an exception occurs inside the `try` block, Python looks for a matching `except` block.

### Example

```python
try:
    result = 10 / 0
```

This raises a `ZeroDivisionError`.

---

## 2. `except`

The `except` block is used to **catch and handle an exception** raised inside the `try` block.

```python
try:
    result = 10 / 0
except ZeroDivisionError:
    print("Cannot divide by zero")
```

Output:

```text
Cannot divide by zero
```

The `except` block runs only when the corresponding exception occurs.

It is generally better to catch **specific exceptions** rather than catching every exception.

```python
try:
    age = int("abc")
except ValueError:
    print("Invalid age")
```

---

## 3. `else`

The `else` block executes **only when the `try` block completes successfully without raising an exception**.

```python
try:
    result = 10 / 2
except ZeroDivisionError:
    print("Division by zero")
else:
    print("Result:", result)
```

Output:

```text
Result: 5.0
```

The `else` block is useful for keeping **success-path code separate from code that is being monitored for exceptions**.

For example:

```python
try:
    value = int("100")
except ValueError:
    print("Invalid input")
else:
    print("Successfully converted:", value)
```

---

## 4. `finally`

The `finally` block executes **whether an exception occurs or not**.

```python
try:
    result = 10 / 2
except ZeroDivisionError:
    print("Error")
finally:
    print("Execution completed")
```

Output:

```text
Execution completed
```

Even if an exception occurs:

```python
try:
    result = 10 / 0
except ZeroDivisionError:
    print("Cannot divide by zero")
finally:
    print("Execution completed")
```

Output:

```text
Cannot divide by zero
Execution completed
```

`finally` is commonly used for **cleanup operations**, such as releasing resources.

---

## Complete Example

```python
try:
    num = int(input("Enter a number: "))
    result = 100 / num

except ValueError:
    print("Please enter a valid integer")

except ZeroDivisionError:
    print("Number cannot be zero")

else:
    print("Result:", result)

finally:
    print("Program finished")
```

### If the user enters `10`

```text
Result: 10.0
Program finished
```

### If the user enters `0`

```text
Number cannot be zero
Program finished
```

### If the user enters `abc`

```text
Please enter a valid integer
Program finished
```

Notice that `finally` executes in all three cases.

---

## Execution Flow

The general flow is:

```text
             try
              |
       Exception occurs?
          /          \
        Yes           No
         |             |
      except          else
         \             /
          \           /
           finally
              |
            End
```

More precisely:

```text
try
 ↓
Exception?
 ├── Yes → matching except
 │
 └── No  → else
          ↓
       finally
          ↓
         End
```

If an exception is not handled by any matching `except`, the `finally` block still runs before the exception propagates further.

## Practical Example: File Handling

`finally` can be used to ensure a resource is cleaned up.

```python
file = None

try:
    file = open("data.txt", "r")
    data = file.read()

except FileNotFoundError:
    print("File not found")

finally:
    if file is not None:
        file.close()
```

However, in modern Python, a **context manager** is usually preferred for file handling:

```python
with open("data.txt", "r") as file:
    data = file.read()
```

The `with` statement automatically handles resource cleanup, even when an exception occurs.

## `try` vs `else`

A common interview question is why we need `else` when we can simply put code after `try/except`.

Consider:

```python
try:
    value = int("100")
except ValueError:
    print("Invalid input")
else:
    process(value)
```

The `else` block ensures that `process(value)` runs only when the **try block succeeds** and keeps `process()` outside the exception-catching region.

This is useful because an exception raised by `process(value)` will not accidentally be caught by the `except ValueError` intended for `int()`.

---

## `finally` and `return`

`finally` executes even when `try` or `except` contains a `return`.

```python
def test():
    try:
        return 10
    finally:
        print("Cleanup")

print(test())
```

Output:

```text
Cleanup
10
```

Because `finally` is intended for cleanup, avoid using `return` inside `finally` unless you have a very specific reason. A `return` in `finally` can override a return value or suppress an exception.

## ML Example

In an ML pipeline, these blocks can be useful when loading a model or processing data:

```python
try:
    model = load_model("model.pkl")
    prediction = model.predict(data)

except FileNotFoundError:
    print("Model file not found")

except ValueError:
    print("Invalid input data")

else:
    print("Prediction successful:", prediction)

finally:
    print("Prediction process completed")
```

In production, instead of simply printing errors, applications would typically use **logging, appropriate error propagation, monitoring, and recovery strategies**.

---

## Common Mistakes

* Using `else` as another `except`. It is not; `else` runs when **no exception occurs**.
* Assuming `finally` runs only when an exception occurs. It normally runs in both success and failure cases.
* Catching every exception with a broad `except` when a specific exception can be handled.
* Silently ignoring errors using:

```python
except Exception:
    pass
```

* Putting too much code inside `try`, making it difficult to identify which operation actually failed.

### Interview Takeaway

> **“`try` contains code that may raise an exception, `except` handles the matching exception, `else` executes when the `try` block succeeds without an exception, and `finally` executes regardless of whether an exception occurred. `finally` is commonly used for cleanup, while `else` separates the successful execution path from the exception-handling logic.”**
