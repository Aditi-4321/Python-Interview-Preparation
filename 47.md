# Question 47 — How do you read and write files safely?

## Answer

Files should be handled carefully to avoid **resource leaks, encoding problems, accidental data loss, and corrupted or insecure data**.

In Python, the recommended approach is to use the built-in `open()` function with a **context manager (`with`)**, which automatically closes the file.

---

## 1. Safely Reading a File

```python
with open("data.txt", "r", encoding="utf-8") as file:
    content = file.read()

print(content)
```

### Why use `with`?

The `with` statement automatically closes the file after the block finishes, even if an exception occurs.

Without a context manager:

```python
file = open("data.txt", "r")
content = file.read()
file.close()
```

If an exception occurs before `close()`, the file may remain open.

Therefore, `with open(...)` is preferred.

---

## 2. Reading Line by Line

For large files, avoid loading the entire file into memory.

```python
with open("data.txt", "r", encoding="utf-8") as file:
    for line in file:
        print(line.strip())
```

This processes the file incrementally and is much more memory-efficient for large datasets.

### Example

Suppose a log file contains millions of records. Instead of:

```python
content = file.read()
```

which may consume a large amount of memory, process one line at a time.

This is particularly useful in **data preprocessing and ML pipelines**.

---

## 3. Safely Writing to a File

```python
with open("output.txt", "w", encoding="utf-8") as file:
    file.write("Machine Learning\n")
    file.write("Python Programming\n")
```

The `"w"` mode creates the file if it doesn't exist, but **overwrites existing contents**.

Therefore, use `"w"` carefully when existing data must be preserved.

---

## 4. Appending Data

If we want to add data without deleting existing content, use `"a"` mode.

```python
with open("output.txt", "a", encoding="utf-8") as file:
    file.write("New record\n")
```

Common modes:

| Mode   | Meaning                                      |
| ------ | -------------------------------------------- |
| `"r"`  | Read                                         |
| `"w"`  | Write and overwrite                          |
| `"a"`  | Append                                       |
| `"x"`  | Create a new file; fail if it already exists |
| `"rb"` | Read binary                                  |
| `"wb"` | Write binary                                 |

Modes can also be combined, such as `"r+"` for reading and writing.

---

## 5. Handling File Errors

File operations can fail because the file doesn't exist, permissions are insufficient, or another OS-level problem occurs.

```python
try:
    with open("data.txt", "r", encoding="utf-8") as file:
        content = file.read()

except FileNotFoundError:
    print("File does not exist.")

except PermissionError:
    print("Permission denied.")

except OSError as e:
    print("File operation failed:", e)
```

It is better to catch **specific exceptions** when possible rather than using a bare `except`.

---

## 6. Handling Large Files Efficiently

For a large file, use streaming rather than `read()`.

```python
count = 0

with open("data.txt", "r", encoding="utf-8") as file:
    for line in file:
        count += 1

print("Number of lines:", count)
```

The file is processed incrementally, so memory usage does not grow proportionally with the complete file size.

For very large binary data, reading in chunks is another useful approach:

```python
with open("data.bin", "rb") as file:
    while chunk := file.read(8192):
        process(chunk)
```

---

## 7. Use the Correct Encoding

Text files should generally be opened with an explicit encoding when portability matters.

```python
with open("data.txt", "r", encoding="utf-8") as file:
    content = file.read()
```

Using the correct encoding helps prevent errors such as `UnicodeDecodeError` when processing non-ASCII text.

---

## 8. Safely Handling File Paths

When file paths come from users or external input, do not blindly construct paths.

For example, accepting:

```text
../../secret.txt
```

could potentially allow **path traversal**.

For applications that accept user-controlled paths, validate and constrain the path to an allowed directory.

For example, `pathlib` provides a modern way to work with paths:

```python
from pathlib import Path

base_dir = Path("uploads").resolve()
file_path = (base_dir / "data.txt").resolve()

if base_dir in file_path.parents:
    with file_path.open("r", encoding="utf-8") as file:
        content = file.read()
```

The exact validation should depend on the application and threat model.

---

## 9. Safely Writing Important Data

When writing important files, simply using `"w"` can be risky because it can replace the existing file.

For critical data, applications may use an **atomic-write pattern**:

1. Write the new content to a temporary file.
2. Ensure the write succeeds.
3. Replace the original file with the completed temporary file.

This reduces the risk of leaving a partially written file if the process fails during writing.

---

## 10. Working with CSV and JSON

For structured data, use appropriate libraries instead of manually parsing strings.

### JSON

```python
import json

data = {
    "name": "Aditi",
    "skills": ["Python", "ML"]
}

with open("data.json", "w", encoding="utf-8") as file:
    json.dump(data, file, indent=4)
```

Reading:

```python
with open("data.json", "r", encoding="utf-8") as file:
    data = json.load(file)
```

### CSV

Python's `csv` module can be used for CSV files:

```python
import csv

with open("data.csv", "r", newline="", encoding="utf-8") as file:
    reader = csv.DictReader(file)

    for row in reader:
        print(row)
```

For large-scale data analysis, tools such as **Pandas** or **PyArrow** may be more appropriate depending on the workload.

## 11. File Handling in ML Projects

File handling is common in ML workflows:

```text
Raw Dataset
     ↓
Read CSV/JSON
     ↓
Validate Data
     ↓
Preprocess
     ↓
Save Processed Data
     ↓
Train Model
```

For example, an ML pipeline may read a large CSV file in chunks rather than loading everything into memory at once.

Production systems should also consider:

* File permissions
* Input validation
* Encoding
* Large-file memory usage
* Logging failures
* Atomic writes for important artifacts
* Safe handling of user-provided paths
* Data integrity and backups
* Temporary-file cleanup

## Common Mistakes

### 1. Forgetting to close files

Prefer:

```python
with open("data.txt", "r") as file:
    data = file.read()
```

instead of manually managing `close()`.

### 2. Accidentally overwriting data

```python
open("data.txt", "w")
```

can erase existing content.

Use `"a"` when you need to append.

### 3. Loading huge files completely into memory

Avoid:

```python
data = file.read()
```

for files that may be very large. Stream or process them in chunks.

### 4. Using unsafe user-controlled paths

Validate paths before opening them.

### 5. Catching every exception blindly

Avoid:

```python
try:
    ...
except:
    pass
```

It can hide real problems and make debugging difficult.

---

## Interview Takeaway

> **The safest general pattern for file handling in Python is to use `with open(...)` so resources are automatically closed. Use the correct mode and encoding, handle specific exceptions, stream large files when necessary, validate untrusted paths, and use appropriate libraries for structured data such as CSV and JSON.**

## Interview Follow-up

**Q: Why is `with open()` preferred over manually calling `close()`?**

Because the context manager guarantees that the file is closed when the block exits, including when an exception occurs. It therefore provides safer and cleaner resource management.
