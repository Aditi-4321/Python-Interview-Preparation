# Question 68 — What is asynchronous programming in Python?

## Answer

**Asynchronous programming** is a programming approach where a program can start an operation that may take time, such as a network request, and **work on other tasks while waiting** instead of blocking the entire flow of execution.

In Python, asynchronous programming is commonly implemented using the **`asyncio`** library with:

* `async`
* `await`
* Coroutines
* An event loop
* Tasks

The key idea is:

> **Asynchronous programming improves concurrency for tasks that spend significant time waiting, especially I/O-bound operations.**

---

## 1. Synchronous vs Asynchronous

### Synchronous execution

Suppose we have three API requests:

```text
Request 1 → wait → complete
Request 2 → wait → complete
Request 3 → wait → complete
```

If each request takes 2 seconds, the total time may be around:

```text
2 + 2 + 2 = 6 seconds
```

The program waits for each operation before starting the next one.

### Asynchronous execution

With asynchronous programming:

```text
Request 1 → waiting ───────→ complete
Request 2 → waiting ───→ complete
Request 3 → waiting ──────→ complete
```

While Request 1 is waiting for a response, the program can work on Request 2 or Request 3.

The total time can therefore be closer to the duration of the slowest overlapping operation, plus scheduling/processing overhead.

---

# 2. `async` and `await`

A basic asynchronous function is called a **coroutine function**:

```python id="5h3t7d"
import asyncio

async def work():
    print("Starting")
    await asyncio.sleep(2)
    print("Finished")
```

`async def` defines a coroutine function.

`await` tells Python:

> "Pause this coroutine until this awaitable operation is ready, and allow the event loop to run other tasks."

---

## 3. Running an asynchronous function

We can run it using `asyncio.run()`:

```python id="zq9c3m"
import asyncio

async def work():
    print("Starting")
    await asyncio.sleep(2)
    print("Finished")

asyncio.run(work())
```

The important point is that:

```python
await asyncio.sleep(2)
```

does **not** block the event loop in the same way as:

```python
import time

time.sleep(2)
```

The asynchronous sleep gives the event loop an opportunity to run other asynchronous tasks.

---

# 4. Running multiple tasks concurrently

Consider:

```python id="b1q6v4"
import asyncio

async def work(name, delay):
    print(f"{name} started")
    await asyncio.sleep(delay)
    print(f"{name} finished")

async def main():
    await asyncio.gather(
        work("Task 1", 2),
        work("Task 2", 2),
        work("Task 2", 2)
    )

asyncio.run(main())
```

The three coroutines can make progress concurrently while waiting.

Conceptually:

```text
Task 1 ── waiting ──────────→ done
Task 2 ── waiting ──────────→ done
Task 3 ── waiting ──────────→ done
             ↑
       Event loop switches
       between ready tasks
```

This can be much more efficient than waiting for each I/O operation sequentially.

---

# 5. What is the event loop?

The **event loop** is the mechanism that manages and schedules asynchronous tasks.

Conceptually:

```text
              Event Loop
                  │
       ┌──────────┼──────────┐
       ↓          ↓          ↓
    Task 1      Task 2      Task 3
       │          │          │
    waiting    ready       waiting
       │          │          │
       └──────────┼──────────┘
                  ↓
        Run whichever task
          can make progress
```

When a coroutine reaches an `await` that is waiting for I/O, the event loop can run another ready coroutine.

This is called **cooperative concurrency** because coroutines voluntarily give control back to the event loop at suspension points such as `await`.

---

# 6. Asynchronous programming is not the same as parallelism

This is a very important interview distinction.

### Asynchronous programming

Primarily provides **concurrency**.

Multiple tasks can make progress during overlapping periods.

### Parallelism

Means multiple operations actually execute simultaneously, typically on different CPU cores.

Therefore:

> **`asyncio` does not automatically make CPU-bound Python code run in parallel.**

For example:

```python id="4zv1q0"
async def heavy_work():
    for i in range(100_000_000):
        ...
```

If this performs heavy CPU computation without yielding, it can block the event loop.

For CPU-heavy work, consider:

* Multiprocessing
* Native/compiled libraries
* Vectorization
* GPU computing

---

# 7. When should you use asynchronous programming?

Asynchronous programming is especially useful for **I/O-bound applications with many concurrent operations**.

Examples:

### Web/API requests

```text
Application
 ├── API request 1 → waiting
 ├── API request 2 → waiting
 ├── API request 3 → waiting
 └── API request 4 → waiting
```

### Web servers

Frameworks such as FastAPI can use asynchronous endpoints for suitable I/O-heavy workloads.

### Database operations

If the database driver supports asynchronous operations, multiple queries can be handled concurrently.

### Network applications

Examples include:

* Web scraping
* API clients
* WebSockets
* Network services
* Microservices communicating with other services

### File operations

Async file handling can be useful in suitable applications, although the exact benefit depends on the operating system and library implementation.

# 8. Threading vs Asyncio

Both can help with I/O-bound work, but their models differ.

| Feature                    | Threading                                         | Asyncio                      |
| -------------------------- | ------------------------------------------------- | ---------------------------- |
| Execution model            | Multiple threads                                  | Coroutines + event loop      |
| Context switching          | Managed by OS/runtime                             | Cooperative                  |
| Memory per concurrent task | Generally higher                                  | Generally lightweight        |
| Best suited for            | I/O-bound work, blocking APIs                     | High-volume async I/O        |
| Code style                 | Normal functions                                  | `async` / `await`            |
| CPU parallelism            | Limited for Python bytecode under traditional GIL | No automatic CPU parallelism |

A major advantage of `asyncio` is that thousands of lightweight I/O tasks can often be managed without creating thousands of OS threads.

---

# 9. Important: Blocking code can ruin async performance

Consider:

```python id="wzv6xd"
import time

async def work():
    time.sleep(5)
```

This is problematic because `time.sleep()` is a blocking call.

It can block the event loop.

Prefer an asynchronous operation when one is available:

```python id="0e5e4r"
import asyncio

async def work():
    await asyncio.sleep(5)
```

The second version allows other asynchronous tasks to run during the wait.

---

# 10. Creating Tasks

You can explicitly schedule a coroutine as an asyncio task:

```python id="s3xq9f"
task = asyncio.create_task(work())
```

The event loop can then run that task concurrently with other tasks.

For example:

```python id="e7z4j1"
async def main():
    task1 = asyncio.create_task(work("A"))
    task2 = asyncio.create_task(work("B"))

    await task1
    await task2
```

`asyncio.gather()` is also commonly used when you want to await multiple operations together.

# 11. AI/ML Relevance

Asynchronous programming can be useful around ML systems even though model training itself is often CPU/GPU-bound.

For example, an AI application might need to:

```text
User Request
     ↓
API call to database
     ↓
Retrieve document
     ↓
Call embedding service
     ↓
Call model/API
     ↓
Return response
```

Many of these operations involve waiting for external services.

An asynchronous architecture can allow the application to handle other requests while individual operations are waiting.

This is particularly relevant to:

* AI APIs
* RAG applications
* Model-serving systems
* LLM applications
* Web applications
* Microservices

However, the actual model inference may still be CPU/GPU-bound and should be optimized using appropriate ML infrastructure rather than simply converting it to `async`.

# 12. Simple Mental Model

Think of a single worker at a restaurant.

### Synchronous

The worker:

```text
Take Order 1
↓
Wait for kitchen
↓
Serve Order 1
↓
Take Order 2
↓
Wait...
```

The worker is idle while waiting.

### Asynchronous

The worker:

```text
Take Order 1
↓
Kitchen working
↓
Take Order 2
↓
Kitchen working
↓
Take Order 3
↓
Serve Order 1
```

The worker uses waiting time to make progress on other tasks.

This is essentially the idea behind asynchronous I/O.

## Common Mistakes

* ❌ Saying async programming automatically creates multiple CPU cores of execution.
* ❌ Using blocking functions inside async code without considering their effect.
* ❌ Thinking `async` automatically makes every function faster.
* ❌ Using async for a purely CPU-bound task.
* ❌ Confusing concurrency with parallelism.
* ❌ Assuming every library supports asynchronous operations simply because Python supports `asyncio`.

## Interview Follow-up

**Q: Is asyncio multithreading?**

> No. `asyncio` primarily uses a single event loop with cooperative coroutines. It is a concurrency model rather than automatic multithreading.

**Q: Can asyncio speed up CPU-bound tasks?**

> Not by itself. CPU-bound code that does not yield can block the event loop. Such workloads usually need multiprocessing, optimized native code, or GPU-based computation.

**Q: When would you choose asyncio over threading?**

> For applications with many concurrent I/O operations, especially when the libraries being used provide good asynchronous APIs.

## Interview Takeaway

> **Asynchronous programming allows a program to handle other tasks while an I/O operation is waiting. In Python, it is commonly implemented using `asyncio`, `async`, `await`, coroutines, and an event loop. It is mainly useful for high-concurrency I/O-bound workloads and should not be confused with CPU parallelism.**
