# Question 44 — How does exception handling work in Python?

## Answer

**Exception handling** in Python is a mechanism for detecting and handling runtime errors without abruptly terminating the program.

An **exception** is an event that occurs during program execution when something unexpected happens, such as:

* Dividing by zero
* Accessing a missing dictionary key
* Opening a file that does not exist
* Converting invalid input to a number
* Using an invalid index

Python mainly uses:

```text
try → except → else → finally
```

to handle exceptions.

---

## Basic Example

```python id="k7m3px"
try:
    x = 10 / 0
except ZeroDivisionError:
    print("Cannot divide by zero")
```

Output:

```text id="r2v8nc"
Cannot divide by zero
```

Here:

* `try` contains code that may raise an exception.
* `except` handles the specific exception.
* Instead of the program terminating with an unhandled exception, the error is handled.

---

## How Exception Handling Works

When Python executes a `try` block:

### Case 1: No exception occurs

The `try` block completes normally.

If an `else` block exists, it executes.

```python id="x4p9qt"
try:
    result = 10 / 2
except ZeroDivisionError:
    print("Invalid division")
else:
    print("Result:", result)
```

Output:

```text id="v8n2km"
Result: 5.0
```

### Case 2: Exception occurs

Python immediately stops executing the remaining statements in the `try` block and searches for a matching `except` block.

```python id="c5w7zs"
try:
    result = 10 / 0
    print("This will not execute")
except ZeroDivisionError:
    print("Division by zero")
```

Output:

```text id="m3q6yr"
Division by zero
```

### Case 3: `finally`

The `finally` block executes whether an exception occurs or not.

```python id="n8t2vk"
try:
    print("Processing")
except Exception:
    print("Error occurred")
finally:
    print("Cleanup completed")
```

This is commonly used for cleanup operations such as closing resources.

---

## `try`, `except`, `else`, and `finally`

### `try`

Contains code that may raise an exception.

### `except`

Handles an exception.

```python id="z6r1wp"
try:
    value = int("abc")
except ValueError:
    print("Invalid number")
```

### `else`

Runs only when the `try` block completes without an exception.

```python id="q4m8xs"
try:
    value = int("100")
except ValueError:
    print("Invalid input")
else:
    print("Conversion successful")
```

### `finally`

Runs regardless of whether an exception occurred.

```python id="j3v7nk"
try:
    value = 10 / 2
finally:
    print("This always executes")
```

---

## Handling Multiple Exceptions

Different exceptions can be handled separately.

```python id="w9p2mc"
try:
    x = int(input("Enter a number: "))
    result = 10 / x

except ValueError:
    print("Please enter a valid number")

except ZeroDivisionError:
    print("Number cannot be zero")
```

This is preferable to treating every error as the same type because different errors may require different responses.

You can also handle multiple exception types together:

```python id="f6k3xr"
try:
    value = int("abc")
except (ValueError, TypeError):
    print("Invalid value")
```

---

## Catching a General Exception

Python allows:

```python id="p7v4qm"
try:
    result = 10 / 0
except Exception as e:
    print("Error:", e)
```

`Exception` is a broad base class for most ordinary application-level exceptions.

However, you should generally **catch specific exceptions when you know what can go wrong**.

Prefer:

```python id="a2n8wc"
except ValueError:
    ...
```

over:

```python id="d5k9zs"
except Exception:
    ...
```

when a specific exception is expected.

A broad `except Exception` can still be useful at an application boundary for logging, cleanup, or preventing an otherwise unhandled application failure, provided the error is handled appropriately rather than silently ignored.

---

## Raising Exceptions with `raise`

You can deliberately generate an exception using `raise`.

```python id="r8x3mt"
def withdraw(balance, amount):
    if amount > balance:
        raise ValueError("Insufficient balance")

    return balance - amount
```

If:

```python id="c4w7qp"
withdraw(1000, 1500)
```

is called, Python raises:

```text id="n6z1vr"
ValueError: Insufficient balance
```

`raise` is useful for enforcing validation rules and communicating invalid states to the calling code.

---

## Custom Exceptions

You can create your own exception class by inheriting from `Exception`.

```python id="h2m7kx"
class InvalidAgeError(Exception):
    pass


def check_age(age):
    if age < 0:
        raise InvalidAgeError("Age cannot be negative")
```

Now the custom exception can be handled separately:

```python id="v5q8nz"
try:
    check_age(-5)
except InvalidAgeError as e:
    print(e)
```

Custom exceptions are useful when an application has domain-specific error conditions.

---

## Exception Chaining

Python can preserve the relationship between an original exception and a higher-level exception.

```python id="s3x9qp"
try:
    value = int("abc")
except ValueError as e:
    raise RuntimeError("Data conversion failed") from e
```

Here, `ValueError` is the original cause, while `RuntimeError` provides a higher-level description.

This is particularly useful in larger applications where lower-level errors need to be translated into meaningful domain-level errors without losing the original cause.

## Exception Handling in ML Projects

Exception handling is important in ML pipelines because failures can occur during:

* Dataset loading
* File processing
* Data validation
* Model loading
* Feature transformation
* API requests
* Prediction
* Database operations

Example:

```python id="q8m4yz"
def load_data(path):
    try:
        with open(path, "r") as file:
            return file.read()

    except FileNotFoundError:
        print("Dataset file not found")
        return None
```

For production ML systems, it is usually better to **log the exception and propagate or handle it according to the application's requirements**, rather than simply returning `None` and silently continuing.

For example:

```python id="u6p2kr"
import logging

logger = logging.getLogger(__name__)

try:
    model.predict(data)
except ValueError:
    logger.exception("Prediction failed because of invalid input")
```

`logger.exception()` records the error along with traceback information when called inside an exception handler.

## Exception Handling vs Errors

An important distinction is:

* **Exception:** An abnormal event that Python can raise and the program can potentially handle.
* **Error:** A broader term for a problem in a program; some errors may be represented by exceptions.

For example:

```python id="m9w3xs"
10 / 0
```

raises a `ZeroDivisionError` exception.

---

## Common Mistakes

### 1. Using a bare `except`

Avoid:

```python id="p2k7vn"
try:
    risky_operation()
except:
    pass
```

This can hide serious problems, including interrupts and unexpected failures.

Prefer specific exceptions:

```python id="j4x8qm"
except ValueError:
    ...
```

### 2. Silently ignoring exceptions

```python id="c7m2wp"
except Exception:
    pass
```

This makes debugging extremely difficult.

### 3. Catching exceptions too broadly

If you know the expected exception, catch that specific type.

### 4. Using exceptions for normal control flow

Exceptions should generally represent exceptional situations rather than ordinary expected program decisions.

### 5. Losing the original error

When translating exceptions, use exception chaining when appropriate:

```python id="r5n9zk"
raise RuntimeError("Processing failed") from e
```

## Interview Follow-up

**1. What is the difference between `raise` and `except`?**
`raise` is used to explicitly generate an exception, while `except` is used to catch and handle an exception.

**2. What is the purpose of `finally`?**
`finally` contains cleanup code that should run whether an exception occurs or not.

**3. Why should we catch specific exceptions instead of using `except Exception` everywhere?**
Specific exceptions make error handling more precise and prevent unrelated failures from being accidentally hidden.

### Interview Takeaway

> **“Python handles runtime exceptions using `try`, `except`, `else`, and `finally`. The `try` block contains potentially failing code, `except` handles matching exceptions, `else` runs when no exception occurs, and `finally` is used for cleanup that should happen regardless of the outcome. Python also supports explicitly raising exceptions, custom exceptions, and exception chaining.”**
