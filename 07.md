## Question 7 — What is the difference between `==` and `is`?

### Answer

Both `==` and `is` are comparison operators in Python, but they answer **different questions**:

* `==` → **Are these two objects equal in value?**
* `is` → **Are these two references pointing to the exact same object?**

A simple way to remember:

> **`==` checks equality; `is` checks identity.**

---

## 1. `==` — Equality Comparison

The `==` operator checks whether two objects are **equal according to their equality comparison**.

Example:

```python
a = [1, 2, 3]
b = [1, 2, 3]

print(a == b)
```

Output:

```text
True
```

Although `a` and `b` are different list objects, they contain equal elements.

Conceptually:

```text
a ───► [1, 2, 3]

b ───► [1, 2, 3]
```

Different objects, but equal values.

---

## 2. `is` — Identity Comparison

The `is` operator checks whether two names refer to the **same object**.

Using the same example:

```python
a = [1, 2, 3]
b = [1, 2, 3]

print(a is b)
```

Output:

```text
False
```

There are two separate list objects.

However:

```python
a = [1, 2, 3]
b = a

print(a == b)
print(a is b)
```

Output:

```text
True
True
```

Here:

```text
a ─────┐
       ├──► [1, 2, 3]
b ─────┘
```

Both names refer to the exact same object.

---

## 3. Comparison Table

| Aspect        | `==`                              | `is`                         |
| ------------- | --------------------------------- | ---------------------------- |
| Checks        | Equality                          | Object identity              |
| Main question | "Do these objects compare equal?" | "Are these the same object?" |
| Works through | Equality comparison               | Identity                     |
| Common use    | Comparing values                  | Checking object identity     |
| Example       | `a == b`                          | `a is b`                     |

---

## 4. Important Example with Mutable Objects

```python
a = [10, 20]
b = a

b.append(30)

print(a)
print(b)
print(a == b)
print(a is b)
```

Output:

```text
[10, 20, 30]
[10, 20, 30]
True
True
```

Why?

Because `a` and `b` refer to the same list object.

---

Now create a separate list:

```python
a = [10, 20]
b = [10, 20]

print(a == b)
print(a is b)
```

Output:

```text
True
False
```

The values are equal, but the objects are different.

---

## 5. The Most Important Use of `is`: `None`

One of the most common and recommended uses of `is` is checking for `None`.

```python
result = None

if result is None:
    print("No result")
```

Why use:

```python
result is None
```

instead of:

```python
result == None
```

Because `None` represents a specific singleton object, and we want to check whether the reference is that exact object.

The standard Python style is:

```python
if value is None:
    ...
```

and:

```python
if value is not None:
    ...
```

---

## 6. A Common Trap with Numbers and Strings

You may sometimes see:

```python
a = 10
b = 10

print(a == b)
print(a is b)
```

Both may print `True` in a particular Python implementation.

This can happen because Python implementations may **reuse/cache certain immutable objects**.

However, you should **not use `is` to compare ordinary values**.

Correct:

```python
a == b
```

Incorrect style:

```python
a is b
```

when your intention is to check whether two values are equal.

Similarly, do not rely on `is` for strings:

```python
a = "hello"
b = "hello"

# Don't use this to compare string values:
a is b

# Use:
a == b
```

Whether two immutable objects happen to be the same object is an implementation detail unless the language specifies the identity relationship.

---

## 7. `is` and `id()`

Object identity can also be observed using `id()`:

```python
a = [1, 2]
b = a

print(a is b)
print(id(a) == id(b))
```

Both comparisons will be `True` because `a` and `b` refer to the same object.

However, in normal Python code, use:

```python
a is b
```

when you need an identity check rather than manually comparing `id()` values.

---

## Practical Example

Suppose an ML function returns either a prediction or `None`:

```python
prediction = get_prediction()

if prediction is None:
    print("Prediction unavailable")
else:
    print("Prediction:", prediction)
```

Here `is` is appropriate because we are checking for the specific `None` object.

On the other hand:

```python
prediction = 0.85

if prediction == 0.85:
    print("Expected prediction")
```

Here `==` is appropriate because we are comparing values.

## Common Mistakes

### Mistake 1: Using `is` for value comparison

```python
if name is "Aditi":
```

Use:

```python
if name == "Aditi":
```

instead.

### Mistake 2: Thinking `is` means "equal"

It does not.

```text
==  → equality
is  → identity
```

Two different objects can be equal:

```python
[1, 2] == [1, 2]  # True
```

while not being identical:

```python
[1, 2] is [1, 2]  # False
```

### Mistake 3: Assuming `is` behavior for integers/strings

Do not rely on implementation-specific object reuse. Use `==` for comparing their values.

---

## Interview Takeaway

A strong interview answer is:

> **`==` checks whether two objects are equal in value, while `is` checks whether two references point to the same object in memory/identity. For example, two separate lists containing `[1, 2]` can satisfy `a == b` but not `a is b`. `is` is commonly used for identity checks such as `value is None`, while `==` should be used for normal value comparisons.**
