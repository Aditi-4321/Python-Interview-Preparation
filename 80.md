# Question 80 — Debug a Python function producing unexpected results because of mutability/reference behavior.

## Answer

A common Python bug occurs when a function modifies a **mutable object** such as a list or dictionary through a reference. The original object outside the function can then change unexpectedly.

### Problem

Consider this code:

```python
def add_item(items):
    items.append("Python")
    return items


data = ["Java", "C++"]

result = add_item(data)

print("Result:", result)
print("Original:", data)
```

### Output

```text
Result: ['Java', 'C++', 'Python']
Original: ['Java', 'C++', 'Python']
```

The unexpected part is that `data` was also modified.

### Why does this happen?

Python variables hold **references to objects**.

Both `data` and the function parameter `items` refer to the **same list object**:

```text
data ───────┐
            ↓
        [Java, C++, Python]
            ↑
items ──────┘
```

Since lists are **mutable**, `items.append()` changes the existing list instead of creating a new list.

This is not exactly "pass by reference"; Python uses **object reference (object sharing) semantics**. The function receives a reference to the same object.

---

## Fix 1: Make a copy before modifying

If the function should not modify the original list:

```python
def add_item(items):
    new_items = items.copy()
    new_items.append("Python")
    return new_items


data = ["Java", "C++"]

result = add_item(data)

print("Result:", result)
print("Original:", data)
```

### Output

```text
Result: ['Java', 'C++', 'Python']
Original: ['Java', 'C++']
```

Now `new_items` refers to a different list.

---

## Fix 2: Use slicing for a shallow copy

For a list, this also creates a new outer list:

```python
def add_item(items):
    new_items = items[:]
    new_items.append("Python")
    return new_items
```

Both `items.copy()` and `items[:]` create a **shallow copy**.

---

## Important: Shallow vs Deep Copy

Consider a nested list:

```python
data = [[1, 2], [3, 4]]

new_data = data.copy()

new_data[0].append(99)

print(data)
```

Output:

```text
[[1, 2, 99], [3, 4]]
```

Why did the original change?

Because a shallow copy creates a new outer list, but the nested lists are still shared:

```text
data     ───────→ [ list1, list2 ]
                         ↑
new_data ───────→ [ list1, list2 ]
```

If completely independent nested objects are required, use `copy.deepcopy()`:

```python
import copy

data = [[1, 2], [3, 4]]

new_data = copy.deepcopy(data)

new_data[0].append(99)

print(data)
print(new_data)
```

Output:

```text
[[1, 2], [3, 4]]
[[1, 2, 99], [3, 4]]
```

## Another Common Bug: Mutable Default Arguments

This is another important mutability-related problem:

```python
def add_item(item, items=[]):
    items.append(item)
    return items


print(add_item("Python"))
print(add_item("Java"))
```

Output:

```text
['Python']
['Python', 'Java']
```

The same default list is reused across function calls.

### Correct approach

Use `None` as the default:

```python
def add_item(item, items=None):
    if items is None:
        items = []

    items.append(item)
    return items


print(add_item("Python"))
print(add_item("Java"))
```

Output:

```text
['Python']
['Java']
```

## How to Debug Reference/Mutability Problems

When unexpected changes occur, check:

### 1. Is the object mutable?

Common mutable objects:

```text
list
dict
set
bytearray
```

### 2. Are two variables referring to the same object?

Use `is`:

```python
a = [1, 2, 3]
b = a

print(a is b)
```

Output:

```text
True
```

### 3. Are you accidentally modifying the object?

Operations such as these mutate a list:

```python
append()
extend()
insert()
remove()
sort()
reverse()
```

Whereas operations such as slicing generally create a new list:

```python
new_list = old_list[:]
```

### 4. Use `id()` when debugging

```python
a = [1, 2, 3]
b = a

print(id(a))
print(id(b))
```

The same ID indicates that both names refer to the same object.

## ML/Data Science Relevance

This issue can occur when preprocessing datasets or configuration dictionaries.

For example:

```python
def preprocess(config):
    config["normalize"] = True
    return config
```

If the caller expects the original configuration to remain unchanged, this function causes an unintended mutation.

A safer approach can be:

```python
def preprocess(config):
    new_config = config.copy()
    new_config["normalize"] = True
    return new_config
```

For nested configuration structures, a deep copy may be required depending on what is being modified.

---

## Common Mistakes

* Assuming Python always copies objects when passing them to functions.
* Calling this simply "pass by reference."
* Using `.copy()` when nested objects also need to be independent.
* Using mutable objects such as `[]` or `{}` as default arguments.
* Using `is` to compare values instead of checking object identity.
* Modifying shared configuration/data unintentionally.

### Interview Follow-up

**Q: Is Python pass-by-value or pass-by-reference?**

A good interview explanation is:

> Python uses **object reference (object sharing) semantics**. A function receives a reference to the same object. If that object is mutable, the function can modify the original object; if a new object is assigned to the parameter, that assignment does not replace the caller's variable.

### Interview Takeaway

> When debugging unexpected changes, check whether multiple variables or function parameters refer to the **same mutable object**. Use a **shallow copy** for independent outer containers and `deepcopy()` when nested mutable objects must also be independent.
