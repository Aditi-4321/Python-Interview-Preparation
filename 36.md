# Question 36 — What is encapsulation?

## Answer

**Encapsulation** is one of the fundamental principles of **Object-Oriented Programming (OOP)**. It means **bundling data (attributes) and the methods that operate on that data inside a class, while controlling how the internal data is accessed or modified**.

In simple terms:

> **Encapsulation = Data + Methods + Controlled Access**

### Example

```python
class BankAccount:
    def __init__(self, balance):
        self.__balance = balance

    def deposit(self, amount):
        if amount > 0:
            self.__balance += amount

    def get_balance(self):
        return self.__balance


account = BankAccount(5000)

account.deposit(1000)

print(account.get_balance())
```

### How does this demonstrate encapsulation?

Here:

* `__balance` represents the object's internal data.
* `deposit()` controls how the balance is modified.
* `get_balance()` provides controlled access to the balance.
* `__balance` uses Python's **name-mangling mechanism**, making accidental direct access from outside the class less likely.

Instead of allowing code to freely modify the balance, the class provides methods that can validate the operation.

For example:

```python
account.deposit(-500)
```

The `deposit()` method can reject the invalid amount.

---

## Why is Encapsulation Important?

### 1. Data Protection

It helps prevent uncontrolled modification of an object's internal state.

### 2. Controlled Access

Methods can validate or process data before modifying it.

### 3. Maintainability

The internal implementation of a class can change without requiring changes in the code that uses the class.

### 4. Better Organization

Related data and operations are kept together inside a class.

### 5. Reduced Coupling

Other parts of the program interact with the class through its intended interface instead of depending directly on its internal implementation.

## Access Conventions in Python

Python does not enforce private members in exactly the same way as languages such as Java or C++. Instead, Python commonly uses naming conventions and name mangling.

```python
class Student:
    def __init__(self):
        self.name = "Aditi"       # Public
        self._college = "MMMUT"  # Protected-style convention
        self.__marks = 90         # Name-mangled
```

### Public

```python
self.name
```

Can normally be accessed from anywhere.

### Protected-style

```python
self._college
```

A single underscore indicates that the attribute is intended for internal/subclass use by convention. Python does not strictly enforce this restriction.

### Private-style

```python
self.__marks
```

Python performs **name mangling**, internally changing the name approximately to:

```text
_Student__marks
```

This is intended mainly to prevent accidental access and name conflicts, not to provide absolute security.

---

## Encapsulation vs Abstraction

These concepts are related but different.

| Concept           | Main Idea                                                                    |
| ----------------- | ---------------------------------------------------------------------------- |
| **Encapsulation** | Bundles data and methods together and controls access to internal state      |
| **Abstraction**   | Hides unnecessary implementation details and exposes essential functionality |

For example, a `BankAccount` class encapsulates the balance and operations, while the user does not need to know the internal implementation of how the balance is stored or updated.

## ML Example

Encapsulation is also useful when designing machine-learning components.

```python
class Model:
    def __init__(self):
        self.__weights = [0.2, 0.5]

    def predict(self, x):
        return sum(w * v for w, v in zip(self.__weights, x))


model = Model()

print(model.predict([2, 3]))
```

Here:

* `__weights` represents the model's internal state.
* `predict()` provides the intended way to use the model.
* The internal representation of the weights can later be changed without changing how the caller uses `predict()`.

In real ML frameworks such as PyTorch, model classes similarly encapsulate parameters, layers, and model operations.

---

## Common Mistakes

* **Encapsulation does not simply mean making variables private.** It also involves bundling state and behavior and providing a controlled interface.
* Python's `__variable` is **not absolute private access**; it uses name mangling.
* **Encapsulation and abstraction are not the same concept.**
* A single underscore `_variable` is a convention, not an enforced access restriction.

## Interview Follow-up

**1. Does Python have truly private variables?**
Not in the same strict sense as some languages. Python uses name mangling for double-underscore attributes.

**2. What is name mangling?**
For an attribute such as `__marks` inside class `Student`, Python internally changes its name approximately to `_Student__marks` to reduce accidental access and naming conflicts.

**3. What is the difference between encapsulation and abstraction?**
Encapsulation focuses on **bundling data and behavior and controlling access**, while abstraction focuses on **hiding unnecessary implementation details and exposing essential functionality**.

### Interview Takeaway

> **“Encapsulation is an OOP principle in which data and the methods operating on that data are bundled inside a class, with controlled access to the object's internal state. In Python, encapsulation is commonly implemented using public attributes, underscore conventions, and name mangling with double underscores.”**
