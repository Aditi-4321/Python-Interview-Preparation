# Question 31 — What are local, global, and nonlocal variables?

## Answer

**Local, global, and nonlocal** describe where a variable belongs in Python's scope hierarchy and how it can be accessed or modified.

The main distinction is:

* **Local** → belongs to the current function.
* **Global** → belongs to the module/program level.
* **Nonlocal** → belongs to an enclosing function and is used by a nested function.

---

## 1. Local Variable

A variable created inside a function is normally a **local variable**.

```python
def calculate():
    x = 10
    print(x)

calculate()
```

Here, `x` is local to `calculate()`.

It cannot normally be accessed directly outside the function:

```python
def calculate():
    x = 10

calculate()
print(x)       # NameError
```

### Important point

A local variable can have the same name as a global variable. They are separate bindings.

```python
x = 100

def show():
    x = 20
    print(x)

show()
print(x)
```

Output:

```text
20
100
```

The `x` inside `show()` is local and does not change the global `x`.

---

# 2. Global Variable

A variable defined outside functions, at the module level, is a **global variable** within that module.

```python
x = 100

def show():
    print(x)

show()
```

The function can read the global `x`.

### Modifying a global variable

If we want to **assign a new value** to a global variable from inside a function, we need the `global` keyword.

```python
x = 100

def change():
    global x
    x = 200

change()

print(x)
```

Output:

```text
200
```

`global x` tells Python that the assignment should use the module-level `x`.

### Why avoid excessive global variables?

Global state can make programs harder to:

* test,
* debug,
* maintain,
* reason about.

In larger applications and ML pipelines, passing data through function parameters and return values is often clearer.

---

# 3. Nonlocal Variable

A **nonlocal variable** is a variable defined in an **enclosing function** and accessed or modified by a nested function.

Consider:

```python
def outer():
    x = 10

    def inner():
        print(x)

    inner()

outer()
```

Here:

```text
outer()
 └── x = 10
      └── inner() can access x
```

`x` is not local to `inner()` and not global. It belongs to the enclosing `outer()` function.

### Modifying the enclosing variable

If `inner()` wants to modify `x`, use `nonlocal`:

```python
def outer():
    x = 10

    def inner():
        nonlocal x
        x += 1

    inner()
    print(x)

outer()
```

Output:

```text
11
```

Without `nonlocal`, an assignment such as `x += 1` would make Python treat `x` as local to `inner()`, causing an `UnboundLocalError` because it tries to read that local `x` before it has been assigned.

---

# Local vs Global vs Nonlocal

| Type         | Where it is defined      | Where it belongs    | Keyword                   |
| ------------ | ------------------------ | ------------------- | ------------------------- |
| **Local**    | Inside current function  | Current function    | Usually none              |
| **Global**   | Outside functions        | Module/global scope | `global` for assignment   |
| **Nonlocal** | In an enclosing function | Enclosing function  | `nonlocal` for assignment |

### Easy way to remember

```text
Local     → current function
Global    → outside functions / module
Nonlocal  → outer function of a nested function
```

---

# Example Showing All Three

```python
x = "global"

def outer():
    x = "enclosing"

    def inner():
        nonlocal x
        x = "nonlocal"
        print(x)

    inner()
    print(x)

outer()

print(x)
```

Output:

```text
nonlocal
nonlocal
global
```

Why?

1. The outer `x` belongs to `outer()`.
2. `nonlocal x` tells `inner()` to modify that enclosing `x`.
3. The module-level `x` remains unchanged.

---

# Important Connection: LEGB

These variables are closely related to Python's **LEGB name-resolution rule**:

```text
L → Local
E → Enclosing
G → Global
B → Built-in
```

When Python encounters a name, it searches these scopes from the nearest relevant scope outward.

For example:

```python
x = "global"

def outer():
    x = "enclosing"

    def inner():
        print(x)

    inner()

outer()
```

Python finds `x` in the **enclosing** scope because there is no local `x` inside `inner()`.

# ML-Oriented Example

Suppose an ML application has configuration information:

```python
learning_rate = 0.001

def train_model(X, y):
    epochs = 20

    print("Learning rate:", learning_rate)
    print("Epochs:", epochs)
```

Here:

* `learning_rate` → global/module-level variable.
* `epochs` → local variable inside `train_model()`.

In production ML code, it is often better to pass configuration explicitly:

```python
def train_model(X, y, learning_rate, epochs):
    # training logic
    pass
```

This makes dependencies explicit and improves **testability, reproducibility, and maintainability**.

## Common Mistakes

### Mistake 1: Thinking assignment automatically changes a global variable

```python
x = 10

def change():
    x = 20
```

This creates a **local** `x`; it does not change the global one.

Use:

```python
def change():
    global x
    x = 20
```

when modifying the global variable is genuinely intended.

### Mistake 2: Confusing `global` and `nonlocal`

```text
global   → module/global scope
nonlocal → nearest enclosing function scope
```

`nonlocal` cannot be used to refer to a module-level variable.

---

## Interview Takeaway

> **A local variable belongs to the current function, a global variable belongs to the module-level scope, and a nonlocal variable belongs to an enclosing function and can be modified by a nested function using the `nonlocal` keyword.**

### Interview Follow-up

**Q: What is the difference between `global` and `nonlocal`?**
`global` refers to a variable in the module/global scope, while `nonlocal` refers to a variable in an enclosing function.

**Q: When is `nonlocal` useful?**
It is mainly useful with **nested functions and closures**, where an inner function needs to maintain or modify state from its enclosing function.

**Q: Can `nonlocal` be used at the top level?**
No. It must refer to an existing variable in an enclosing **function** scope.
