## Question 9 — How are strings represented and why are they immutable?

### Answer

In Python, a **string (`str`) is an immutable sequence of Unicode characters**. Strings are used to represent text such as names, sentences, file paths, URLs, and JSON data.

```python
name = "Aditi"
message = "Hello, Python!"
```

### 1. How are strings represented?

Python strings use **Unicode**, which allows a single string type to represent characters from many writing systems, symbols, and emojis.

```python
text = "Hello"
text = "नमस्ते"
text = "你好"
text = "😊"
```

All of these are Python `str` objects.

At the implementation level, especially in **CPython**, strings are represented using an internal Unicode representation that can use different storage widths depending on the characters present. This is an implementation detail; as a Python programmer, the important point is that `str` represents Unicode text.

You can inspect the type with:

```python
text = "Python"
print(type(text))
```

Output:

```text
<class 'str'>
```

---

### 2. Why are strings immutable?

**Immutable** means that once a string object is created, its contents cannot be changed.

For example:

```python
s = "Hello"
s[0] = "h"
```

This produces:

```text
TypeError: 'str' object does not support item assignment
```

Instead, an operation that appears to modify a string actually creates a **new string object**:

```python
s = "Hello"
s = s + " World"

print(s)
```

Output:

```text
Hello World
```

The original `"Hello"` object was not modified. The variable `s` was simply made to refer to a new string object.

### 3. Why is immutability useful?

#### a. Strings are safely shareable

Multiple variables can refer to the same string without one operation unexpectedly changing the value for another variable.

```python
a = "Python"
b = a
```

Since strings cannot be modified in place, there is no risk of `b` changing because `a` somehow modified the same string object.

#### b. Strings can be hashable

Strings can be used as dictionary keys and set elements:

```python
student = {
    "name": "Aditi",
    "course": "MCA"
}
```

This works because strings have a stable hash value while they exist.

> Important: immutability and hashability are related but are **not exactly the same concept**. Hashability is what allows an object to be reliably used as a dictionary key or set element.

#### c. It makes text handling more predictable

Since a string cannot be changed in place, functions receiving a string don't have to worry about another part of the program modifying that same string object.

#### d. It can support implementation optimizations

Because strings cannot change, runtimes can safely reuse or cache certain string objects in appropriate situations. CPython, for example, performs **string interning** for some strings.

---

### 4. Common operations create new strings

```python
s = "python"

upper_s = s.upper()
new_s = s.replace("p", "P")

print(s)        # python
print(upper_s)  # PYTHON
print(new_s)    # Python
```

The original `s` remains unchanged.

---

### 5. String immutability vs mutable lists

This is a common interview comparison:

```python
# String - immutable
s = "abc"
# s[0] = "A"     # TypeError

# List - mutable
items = ["a", "b", "c"]
items[0] = "A"

print(items)
```

Output:

```text
['A', 'b', 'c']
```

The list changes in place, whereas the string cannot.

---

### Interview Takeaway

> **Python strings are immutable Unicode sequences. Their contents cannot be changed after the string object is created. Operations such as concatenation, replacement, or conversion create a new string object rather than modifying the existing one. Immutability provides predictable sharing, stable hashing, and allows certain runtime optimizations.**

### Interview Follow-up

**Q: If strings are immutable, why does `s = s + "abc"` work?**

Because the original string is not modified. A **new string object** is created, and the name `s` is rebound to that new object.
