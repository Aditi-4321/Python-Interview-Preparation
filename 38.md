# Question 38 — What is polymorphism?

## Answer

**Polymorphism** is one of the fundamental principles of **Object-Oriented Programming (OOP)**. The word *polymorphism* means **"many forms."**

It means that **the same interface, method, or operation can behave differently depending on the object or data type involved**.

In simple terms:

> **Polymorphism allows different objects to respond to the same method or operation in their own way.**

### Basic Example

```python
class Dog:
    def sound(self):
        print("Bark")


class Cat:
    def sound(self):
        print("Meow")


dog = Dog()
cat = Cat()

dog.sound()
cat.sound()
```

Output:

```text
Bark
Meow
```

Both objects have a method called `sound()`, but the behavior is different.

The same method call:

```python
animal.sound()
```

can produce different behavior depending on the actual object.

---

## Why is Polymorphism Important?

### 1. Flexibility

The same code can work with different types of objects.

### 2. Extensibility

New classes can provide their own implementation of a common interface without requiring major changes to existing code.

### 3. Reduced Coupling

Code can depend on what an object **can do** rather than its exact concrete class.

### 4. Cleaner Code

Instead of writing separate conditional logic for every object type, we can call a common method.

For example, instead of:

```python
if type == "dog":
    dog_sound()
elif type == "cat":
    cat_sound()
```

we can use:

```python
animal.sound()
```

and let the object determine the appropriate behavior.

---

## Polymorphism Through Method Overriding

Polymorphism commonly occurs through **method overriding**.

```python
class Animal:
    def sound(self):
        print("Some sound")


class Dog(Animal):
    def sound(self):
        print("Bark")


class Cat(Animal):
    def sound(self):
        print("Meow")


animals = [Dog(), Cat()]

for animal in animals:
    animal.sound()
```

Output:

```text
Bark
Meow
```

The loop does not need to know whether `animal` is a `Dog` or `Cat`.

It simply calls:

```python
animal.sound()
```

Python determines which implementation to execute at runtime.

This is an example of **runtime polymorphism**.

---

## Duck Typing in Python

Python strongly supports **duck typing**.

The idea is:

> **"If it walks like a duck and quacks like a duck, treat it like a duck."**

Python often cares about whether an object supports the required operation rather than whether it belongs to a particular class.

Example:

```python
class Dog:
    def speak(self):
        print("Bark")


class Person:
    def speak(self):
        print("Hello")


def make_speak(obj):
    obj.speak()


make_speak(Dog())
make_speak(Person())
```

Output:

```text
Bark
Hello
```

`make_speak()` does not require the object to inherit from a particular base class. It only requires the object to provide a compatible `speak()` method.

This is an important practical form of polymorphism in Python.

---

## Polymorphism with Built-in Functions

Python's built-in functions also demonstrate polymorphism.

For example:

```python
print(len("Python"))
print(len([10, 20, 30]))
print(len((1, 2, 3)))
```

Output:

```text
6
3
3
```

The same function:

```python
len()
```

works with different types because those objects provide the required length behavior.

Similarly, the `+` operator behaves differently depending on the operands:

```python
print(10 + 20)
print("Hello " + "World")
print([1, 2] + [3, 4])
```

Output:

```text
30
Hello World
[1, 2, 3, 4]
```

This is another example of polymorphic behavior.

## Polymorphism and Method Overloading in Python

A common interview confusion is **method overloading vs overriding**.

### Method Overriding

A child class provides a different implementation of a method inherited from its parent.

```python
class Animal:
    def sound(self):
        print("Sound")


class Dog(Animal):
    def sound(self):
        print("Bark")
```

Python supports this naturally.

### Method Overloading

In languages such as Java, you can define multiple methods with the same name but different parameter lists.

Python does **not** support traditional compile-time method overloading based solely on different parameter lists.

For example, this does not create two overloaded methods:

```python
class Calculator:
    def add(self, a, b):
        return a + b

    def add(self, a, b, c):
        return a + b + c
```

The second `add()` replaces the first one.

Python can achieve similar behavior using techniques such as:

* Default arguments
* `*args`
* Conditional logic
* `functools.singledispatch` for certain function-based dispatch needs

Example using default arguments:

```python
class Calculator:
    def add(self, a, b, c=0):
        return a + b + c
```

Now:

```python
print(Calculator().add(2, 3))
print(Calculator().add(2, 3, 4))
```

## Polymorphism in Machine Learning

Polymorphism is useful in ML systems when different implementations provide a common interface.

For example:

```python
class Model:
    def predict(self, x):
        raise NotImplementedError


class LinearModel(Model):
    def predict(self, x):
        return "Linear prediction"


class TreeModel(Model):
    def predict(self, x):
        return "Tree prediction"


models = [LinearModel(), TreeModel()]

for model in models:
    print(model.predict([1, 2, 3]))
```

Both models expose:

```python
predict()
```

but their implementations can be completely different.

This is useful in ML pipelines because a prediction component can work with different model implementations through a common interface.

---

## Polymorphism vs Inheritance

These concepts are related but not identical.

| Concept               | Main Idea                                                                     |
| --------------------- | ----------------------------------------------------------------------------- |
| **Inheritance**       | Allows a class to derive functionality from another class                     |
| **Polymorphism**      | Allows the same interface/method to have different behavior                   |
| **Method Overriding** | Allows a child class to provide its own implementation of an inherited method |

Polymorphism **can** be implemented using inheritance, but Python's duck typing means polymorphic behavior does not always require inheritance.

---

## Common Mistakes

* Thinking polymorphism means only method overriding.
* Assuming Python supports traditional method overloading like Java.
* Confusing inheritance with polymorphism.
* Assuming polymorphism always requires a common parent class.
* Forgetting that Python's **duck typing** enables polymorphic behavior based on supported operations rather than strict class relationships.

## Interview Follow-up

**1. What is duck typing in Python?**
Duck typing means Python focuses on whether an object supports the required operation or method rather than requiring it to belong to a specific class.

**2. Does Python support method overloading?**
Python does not support traditional compile-time method overloading based solely on different parameter lists. Default arguments, `*args`, or other techniques can provide similar behavior.

**3. What is the difference between overriding and overloading?**
**Overriding** occurs when a child class provides a new implementation of an inherited method. **Overloading** traditionally means multiple methods with the same name but different parameter lists; Python does not support this in the traditional sense.

### Interview Takeaway

> **“Polymorphism means many forms. It allows the same interface or method call to produce different behavior depending on the object. In Python, polymorphism is commonly achieved through method overriding and duck typing, allowing code to work with different object types through a common interface.”**
