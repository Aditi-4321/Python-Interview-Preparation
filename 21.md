# Question 21 — What is a dictionary and how does it work internally?

## Answer

A **dictionary (`dict`)** in Python is a mutable data structure that stores data as **key-value pairs**.

```python
student = {
    "name": "Aditi",
    "age": 21,
    "course": "MCA"
}
```

Here:

* `"name"`, `"age"`, and `"course"` are **keys**.
* `"Aditi"`, `21`, and `"MCA"` are their corresponding **values**.

A dictionary is mainly used when we want to **look up a value using a meaningful key** rather than a numeric index.

---

## 1. Key Properties of a Dictionary

A Python dictionary:

* Stores **key-value pairs**.
* Is **mutable**.
* Keys must be **hashable**.
* Values can be of almost any Python type.
* Keys are unique.
* Supports fast average-case lookup, insertion, and deletion.
* Preserves **insertion order** in modern Python versions.

Example:

```python
student = {
    "name": "Aditi",
    "age": 21
}

print(student["name"])
```

Output:

```text
Aditi
```

---

## 2. How Does a Dictionary Work Internally?

Conceptually, a Python dictionary is implemented using a **hash table**.

The basic idea is:

```text
Key
 ↓
Hash function
 ↓
Hash value
 ↓
Determine location
 ↓
Store / find the key-value pair
```

For example:

```python
data = {
    "name": "Aditi"
}
```

When Python needs to find `"name"`, it approximately does:

```text
"name"
  ↓
hash("name")
  ↓
hash value
  ↓
find appropriate table position
  ↓
retrieve associated value "Aditi"
```

The exact internal implementation is more sophisticated, and details are implementation-dependent. In **CPython**, dictionaries use a highly optimized hash-table design.

---

## 3. What is Hashing?

A **hash function** converts a hashable object into an integer-like hash value.

Python provides the `hash()` function:

```python
print(hash("name"))
```

The exact hash value should not be relied upon across different Python processes because some hashable types, especially strings, use randomized hashing.

For a dictionary key:

```python
student["name"]
```

Python uses the key's hash as part of locating the corresponding dictionary entry.

---

## 4. Why Must Dictionary Keys Be Hashable?

A dictionary needs keys whose hash and equality behavior are stable enough for lookup.

For example, immutable types such as strings and integers can be dictionary keys:

```python
data = {
    "name": "Aditi",
    101: "MCA"
}
```

A tuple can also be a key if **all of its elements are hashable**:

```python
data = {
    (10, 20): "Point"
}
```

But a list cannot be a key:

```python
data = {
    [1, 2]: "value"
}
```

This raises:

```text
TypeError: unhashable type: 'list'
```

The important rule is:

> **Dictionary keys must be hashable; dictionary values do not have this restriction.**

---

## 5. How Does Lookup Work?

Suppose:

```python
student = {
    "name": "Aditi",
    "age": 21
}

print(student["age"])
```

Conceptually:

1. Python calculates the hash of `"age"`.
2. It uses that hash to locate a candidate position.
3. It checks the stored key.
4. If the key matches, Python returns the associated value.

This is why dictionary lookup is generally very fast.

### Average complexity

| Operation               | Average Time |
| ----------------------- | -----------: |
| Lookup `d[key]`         |         O(1) |
| Insert `d[key] = value` |         O(1) |
| Delete `del d[key]`     |         O(1) |
| Membership `key in d`   |         O(1) |

These are **average-case** complexities, not absolute guarantees.

---

## 6. What Happens During a Collision?

Two different keys can sometimes produce the same relevant table location. This is called a **collision**.

For example, conceptually:

```text
Key A ──hash──> position 5
Key B ──hash──> position 5
```

Python's dictionary implementation has mechanisms to handle such collisions and find the correct entry.

Importantly, Python does not assume that equal hash values mean equal objects.

For example:

```python
a == b
```

must still be considered when distinguishing keys.

The important relationship is:

> If `a == b`, their hash values must be equal.
> But equal hash values do not necessarily mean `a == b`.

---

## 7. Why Is Dictionary Lookup Faster Than List Search?

Consider a list:

```python
students = ["Aditi", "Rahul", "Neha", "Aman"]
```

Searching for `"Neha"` may require checking elements one by one:

```text
Aditi → Rahul → Neha
```

So lookup is generally **O(n)**.

With a dictionary:

```python
students = {
    101: "Aditi",
    102: "Rahul",
    103: "Neha"
}
```

Python can use the key's hash to locate the corresponding entry directly on average.

Therefore:

```python
students[103]
```

is generally **O(1) average time**.

---

## 8. Dictionary Keys Are Unique

A dictionary cannot have two separate entries with the same key.

```python
data = {
    "name": "Aditi",
    "name": "Rahul"
}

print(data)
```

Output:

```text
{'name': 'Rahul'}
```

The second assignment replaces the value associated with the existing key.

This is also why:

```python
data["name"] = "Rahul"
```

updates an existing entry rather than creating a duplicate key.

---

## 9. Dictionary Values Can Be Mutable

Keys have hashability requirements, but values can be mutable.

```python
student = {
    "name": "Aditi",
    "skills": ["Python", "SQL"]
}

student["skills"].append("Java")

print(student)
```

Output:

```text
{'name': 'Aditi', 'skills': ['Python', 'SQL', 'Java']}
```

This is completely valid because the list is a **value**, not a key.

---

## 10. Dictionary vs List

| Feature        | Dictionary            | List                   |
| -------------- | --------------------- | ---------------------- |
| Structure      | Key-value pairs       | Ordered elements       |
| Access         | By key                | By index               |
| Average lookup | O(1)                  | O(n) for value search  |
| Keys           | Must be hashable      | Not applicable         |
| Duplicates     | Keys cannot duplicate | Elements can duplicate |
| Mutable        | Yes                   | Yes                    |
| Typical use    | Fast lookup/mapping   | Ordered collection     |

Example:

```python
marks = {
    "Python": 90,
    "DBMS": 85,
    "Java": 88
}
```

This is more natural than storing the same information in a list because we can directly access:

```python
marks["Python"]
```

## 11. Practical Example in an ML/Data Project

Suppose we store model evaluation results:

```python
results = {
    "accuracy": 0.94,
    "precision": 0.91,
    "recall": 0.89,
    "f1_score": 0.90
}
```

We can directly access:

```python
print(results["accuracy"])
```

This is useful when data is naturally represented as **named attributes or mappings**.

Dictionaries are also heavily used for:

* Configuration
* JSON-like data
* API responses
* Feature mappings
* Frequency counting
* Caching
* Lookup tables
* Grouping data

---

## 12. Dictionary and JSON Are Not Exactly the Same

They often look similar:

```python
data = {
    "name": "Aditi",
    "age": 21
}
```

But a Python dictionary is a Python object, while **JSON is a data interchange format**.

For example, JSON is represented as text:

```json
{
    "name": "Aditi",
    "age": 21
}
```

Python's `json` module can convert between compatible Python objects and JSON.

---

## 13. Important Internal Point: Resizing

A dictionary needs enough internal table space to maintain efficient operations.

As entries are added, Python may **resize/reorganize the internal hash table**.

This means insertion is:

> **O(1) average/amortized**, rather than O(1) for every single insertion under every circumstance.

Resizing requires additional work, but it happens periodically rather than for every insertion.

---

## 14. Common Mistakes

### Mistake 1: Saying dictionaries are always O(1)

Better:

> Dictionary lookup, insertion, and deletion are **O(1) on average**.

### Mistake 2: Saying dictionary keys must be immutable

More accurate:

> Dictionary keys must be **hashable**.

Many immutable objects are hashable, but immutability and hashability are not exactly the same concept.

### Mistake 3: Assuming hash values uniquely identify keys

Different objects can have the same hash value. Python also uses equality checks to correctly identify keys.

### Mistake 4: Using a list as a key

```python
d = {[1, 2]: "value"}
```

This fails because lists are unhashable.

### Mistake 5: Assuming dictionary order is arbitrary

Modern Python guarantees that dictionaries **preserve insertion order**. However, order preservation does not mean a dictionary is an index-based data structure.

## Interview Follow-up

**Q: Why are dictionary lookups generally O(1)?**
Because dictionaries use a hash-table-based design that uses the key's hash to locate the corresponding entry without scanning every key.

**Q: Can a tuple be a dictionary key?**
Yes, provided all elements inside the tuple are hashable.

**Q: Why can't a list be a dictionary key?**
Because lists are mutable and therefore unhashable.

**Q: What happens if two keys have the same hash?**
A collision occurs. The dictionary's collision-handling mechanism finds the appropriate entry, and equality checking distinguishes keys.

### Interview Takeaway

> **A Python dictionary is a mutable key-value mapping implemented in CPython using a highly optimized hash-table design. Keys must be hashable. Hashing allows lookup, insertion, and deletion to be O(1) on average, while collisions and periodic resizing are handled internally.**
