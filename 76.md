# Question 76 — Implement common list/string/dictionary operations without relying blindly on built-ins.

## Answer

In interviews, it is useful to understand the **logic behind common operations** instead of only knowing built-in methods such as `max()`, `count()`, `reverse()`, `split()`, or dictionary helpers.

The goal is **not to avoid built-ins in real projects**. Built-ins are usually preferable because they are readable, tested, and often optimized. The purpose of implementing them manually is to demonstrate understanding of:

* Loops
* Indexing
* Conditions
* Data structures
* Time and space complexity
* Edge cases

---

# 1. Find the Maximum Element in a List

Instead of:

```python
max(numbers)
```

implement it manually:

```python
def find_max(numbers):
    if not numbers:
        return None

    largest = numbers[0]

    for num in numbers[1:]:
        if num > largest:
            largest = num

    return largest


numbers = [10, 5, 25, 8, 15]

print(find_max(numbers))
```

Output:

```text
25
```

### Logic

1. Assume the first element is the largest.
2. Compare every remaining element with it.
3. Replace `largest` whenever a bigger value is found.

### Complexity

* Time: **O(n)**
* Extra space: **O(1)**

# 7. Reverse a List In-Place

If we want to avoid creating another list, use two pointers.

```python
def reverse_in_place(numbers):
    left = 0
    right = len(numbers) - 1

    while left < right:
        numbers[left], numbers[right] = numbers[right], numbers[left]

        left += 1
        right -= 1

    return numbers


numbers = [1, 2, 3, 4, 5]

print(reverse_in_place(numbers))
```

Output:

```text
[5, 4, 3, 2, 1]
```

### Complexity

* Time: **O(n)**
* Extra space: **O(1)**

This is a common interview technique.

# 8. Remove Duplicates from a List

For a list of hashable values, a set is an efficient approach:

```python
def remove_duplicates(numbers):
    seen = set()
    result = []

    for num in numbers:
        if num not in seen:
            seen.add(num)
            result.append(num)

    return result


numbers = [1, 2, 2, 3, 1, 4, 3]

print(remove_duplicates(numbers))
```

Output:

```text
[1, 2, 3, 4]
```

This preserves the **first occurrence order**.

### Complexity

* Average time: **O(n)**
* Extra space: **O(n)**

# 9. Find the Second Largest Element

```python
def second_largest(numbers):
    if len(numbers) < 2:
        return None

    largest = None
    second = None

    for num in numbers:
        if largest is None or num > largest:
            second = largest
            largest = num
        elif num != largest and (second is None or num > second):
            second = num

    return second


numbers = [10, 20, 5, 30, 25]

print(second_largest(numbers))
```

Output:

```text
25
```

Here, the implementation finds the **second distinct largest value**.

### Complexity

* Time: **O(n)**
* Extra space: **O(1)**

# 10. Check Whether a String Is a Palindrome

Instead of using slicing:

```python
text == text[::-1]
```

we can use two pointers:

```python
def is_palindrome(text):
    left = 0
    right = len(text) - 1

    while left < right:
        if text[left] != text[right]:
            return False

        left += 1
        right -= 1

    return True


print(is_palindrome("madam"))
print(is_palindrome("hello"))
```

Output:

```text
True
False
```

### Complexity

* Time: **O(n)**
* Extra space: **O(1)**

This demonstrates an important interview pattern: **two pointers**.

# 11. Reverse a String Without Slicing

Instead of:

```python
text[::-1]
```

we can construct the result:

```python
def reverse_string(text):
    result = ""

    for i in range(len(text) - 1, -1, -1):
        result += text[i]

    return result


print(reverse_string("python"))
```

Output:

```text
nohtyp
```

### Important Complexity Note

Repeated string concatenation can result in **O(n²)** behavior because strings are immutable.

For better performance when manually constructing a large string, use a list and join:

```python
def reverse_string(text):
    chars = []

    for i in range(len(text) - 1, -1, -1):
        chars.append(text[i])

    return "".join(chars)
```

This is generally **O(n)** time with **O(n)** extra space.

# 13. Check Whether Two Strings Are Anagrams

Two strings are anagrams if they contain the same characters with the same frequencies.

Example:

```text
listen
silent
```

Manual frequency-counting approach:

```python
def are_anagrams(s1, s2):
    if len(s1) != len(s2):
        return False

    count = {}

    for char in s1:
        count[char] = count.get(char, 0) + 1

    for char in s2:
        if char not in count:
            return False

        count[char] -= 1

        if count[char] < 0:
            return False

    return True


print(are_anagrams("listen", "silent"))
```

Output:

```text
True
```

### Complexity

* Time: **O(n)** average
* Space: **O(k)**

# 14. Split a String Manually

Instead of:

```python
text.split()
```

a simplified implementation for splitting on spaces can be:

```python
def split_words(text):
    words = []
    current = ""

    for char in text:
        if char == " ":
            if current:
                words.append(current)
                current = ""
        else:
            current += char

    if current:
        words.append(current)

    return words


print(split_words("I love Python"))
```

Output:

```text
['I', 'love', 'Python']
```

### Important Note

This is a simplified implementation. Python's actual `str.split()` supports many additional behaviors, including different separators and whitespace handling.

# 15. Join Strings Manually

```python
" ".join(words)
```

a basic implementation is:

```python
def join_words(words, separator):
    result = ""

    for i in range(len(words)):
        result += words[i]

        if i != len(words) - 1:
            result += separator

    return result


words = ["I", "love", "Python"]

print(join_words(words, " "))
```

Output:

```text
I love Python
```

Again, for real code, `" ".join(words)` is preferable because it is clearer and optimized.

# 16. Find the First Non-Repeating Character

This is a common interview problem.

```python
def first_non_repeating(text):
    frequency = {}

    for char in text:
        frequency[char] = frequency.get(char, 0) + 1

    for char in text:
        if frequency[char] == 1:
            return char

    return None


print(first_non_repeating("aabbcdde"))
```

Output:

```text
c
```

### Why two passes?

First pass:

```text
Count every character
```

Second pass:

```text
Find the first character with count = 1
```

### Complexity

* Time: **O(n)**
* Space: **O(k)**

# 17. Create a Dictionary from Two Lists

Given:

```python
keys = ["name", "age", "city"]
values = ["Aditi", 22, "Lucknow"]
```

Manual implementation:

```python
def make_dictionary(keys, values):
    result = {}

    for i in range(len(keys)):
        result[keys[i]] = values[i]

    return result


print(make_dictionary(keys, values))
```

Output:

```text
{'name': 'Aditi', 'age': 22, 'city': 'Lucknow'}
```

### Important Edge Case

If the lists have different lengths, decide what the function should do.

A safer version:

```python
def make_dictionary(keys, values):
    if len(keys) != len(values):
        raise ValueError("Both lists must have the same length")

    result = {}

    for i in range(len(keys)):
        result[keys[i]] = values[i]

    return result
```

def key_with_max_value(data):
    if not data:

# 19. Merge Two Dictionaries Manually

```python
def merge_dicts(first, second):
    result = {}

    for key, value in first.items():
        result[key] = value

    for key, value in second.items():
        result[key] = value

    return result


a = {"name": "Aditi", "age": 22}
b = {"city": "Lucknow", "age": 23}

print(merge_dicts(a, b))
```

Output:

```text
{'name': 'Aditi', 'age': 23, 'city': 'Lucknow'}
```

If the same key exists in both dictionaries, the value from `second` overwrites the earlier value.

### Complexity

* Time: **O(n + m)** average
* Space: **O(n + m)**

# 20. Build a Frequency Dictionary for a List

This is one of the most useful dictionary patterns.

```python
def frequency_count(numbers):

        if num in frequency:

numbers = [1, 2, 2, 3, 1, 2]

print(frequency_count(numbers))
```

Output:

# Built-ins vs Manual Implementation

In **interviews**, manual implementation demonstrates your understanding.

In **real projects**, prefer standard built-ins when they clearly express the intention.

For example:

```python
max(numbers)
```

is normally better production code than:

```python
find_max(numbers)
```

because the built-in is:

* Readable
* Tested
* Well-known
* Usually optimized
* Less code to maintain

So the correct mindset is:

> **Understand how the operation works internally, but use reliable built-ins when they are appropriate in production code.**

---

## Common Mistakes

* ❌ Avoiding all built-ins just to make code look complicated.
* ❌ Forgetting edge cases such as empty lists or strings.
* ❌ Using nested loops when a dictionary/set can reduce complexity.
* ❌ Ignoring duplicate values in "second largest" problems.
* ❌ Repeatedly concatenating large strings with `+=`.
* ❌ Claiming every dictionary/set operation is always O(1); it is generally **average-case O(1)**.
* ❌ Not explaining time and space complexity during an interview.

---

## Interview Follow-up

**Q: Why use a dictionary for frequency counting?**

> A dictionary provides average O(1) lookup and update for hashable keys, allowing us to count frequencies in O(n) average time instead of repeatedly scanning the entire collection.

**Q: How would you reverse a list without using extra space?**

> Use two pointers, one at the beginning and one at the end, swap the elements, and move both pointers toward the center. This takes O(n) time and O(1) extra space.

**Q: Why is `"".join()` preferred over repeated string concatenation?**

> Strings are immutable, so repeated concatenation can create many intermediate strings. Building a list of pieces and using `join()` is generally more efficient for constructing a large string.

## Interview Takeaway

> **Manual implementations of common list, string, and dictionary operations help demonstrate fundamental programming and data-structure skills. The most important interview concepts are loops, indexing, hashing, two-pointer techniques, frequency counting, edge-case handling, and time/space complexity. In production Python, however, reliable built-ins should generally be preferred when they provide clear and efficient solutions.**
