## Question 5 — What is dynamic typing?

### Answer

**Dynamic typing** means that the type of a variable name does not have to be declared explicitly, and the **type is associated with the object at runtime**. A name can also be rebound to objects of different types during program execution.

For example:

```python
value = 10
print(type(value))     # <class 'int'>

value = "Python"
print(type(value))     # <class 'str'>
```

The name `value` first refers to an integer object and later refers to a string object.

Conceptually:

```text
value ───► 10
           int

        ↓ reassignment

value ───► "Python"
           str
```

### Why is Python dynamically typed?

In Python, you normally don't write the variable type explicitly:

```python
age = 21
name = "Aditi"
marks = 85.5
```

Python determines the types from the objects involved.

Compare this with a statically typed language where a variable's declared type is checked more explicitly:

```text
int age = 21;
```

The exact syntax depends on the language, but the key distinction is **when and how type information is checked**.

---

## Dynamic Typing Does NOT Mean "No Types"

This is a common interview trap.

Python is dynamically typed, but **Python is strongly typed** in the sense that objects have types and Python generally does not silently perform arbitrary incompatible type conversions.

For example:

```python
age = 21
name = "Aditi"

print(age + name)
```

This produces a `TypeError` rather than automatically converting one value into the other.

You can explicitly convert when appropriate:

```python
age = 21
text = "Age: " + str(age)

print(text)
```

Output:

```text
Age: 21
```

So:

> **Dynamic typing concerns when/how type information is associated and checked; it does not mean Python has no type system.**

## Dynamic Typing vs Static Typing

| Aspect                                      | Dynamic Typing                         | Static Typing                                      |
| ------------------------------------------- | -------------------------------------- | -------------------------------------------------- |
| Type declaration                            | Often not required                     | Usually explicitly declared or inferred            |
| Type checking                               | Primarily at runtime                   | Primarily at compile/type-check time               |
| Example                                     | Python                                 | Java, C++, C#                                      |
| Variable can refer to different types?      | Yes                                    | Generally restricted by the declared/inferred type |
| Flexibility                                 | High                                   | More constrained                                   |
| Some type errors detected before execution? | Usually fewer without additional tools | More commonly detected before execution            |

### Example

Python:

```python
x = 10
x = "Hello"
```

This is valid because `x` can be rebound to another object.

A statically typed language such as Java would normally require the variable's declared type to remain compatible:

```java
int x = 10;
// x = "Hello";   // Compile-time error
```

## Dynamic Typing and Objects

Remember the concept from the previous question:

> **Python variables are names that refer to objects.**

Therefore, in:

```python
x = 10
```

the name `x` refers to an `int` object.

Later:

```python
x = "Hello"
```

the same name refers to a `str` object.

The **object has the type**, while the name `x` can be rebound.

This is more precise than saying *"the variable changes its type."*

---

## Advantages

Dynamic typing can make Python code:

* Concise
* Flexible
* Quick to prototype
* Convenient for scripting and experimentation

For example, you can write:

```python
data = [10, 20, 30]
```

without first declaring the list's type.

### Trade-off

Because many type errors are discovered during execution, an incorrect type may not be detected until a particular code path runs.

For example:

```python
def calculate_total(a, b):
    return a + b
```

This can work with numbers:

```python
calculate_total(10, 20)
```

but fail for incompatible objects:

```python
calculate_total(10, "20")
```

Python's **type hints** can help developers and static-analysis tools detect many such problems earlier:

```python
def calculate_total(a: int, b: int) -> int:
    return a + b
```

Type hints improve tooling and documentation, but they do **not by themselves turn Python into a statically typed language or enforce the annotation at runtime**.

## Common Mistakes

### Mistake 1: "Dynamic typing means Python doesn't have types."

Incorrect. Python objects have types.

### Mistake 2: "Dynamic typing means no type errors."

Incorrect. Type errors can occur at runtime.

### Mistake 3: "Dynamic typing and weak typing mean the same thing."

They are different concepts.

* **Dynamic/static typing** → primarily concerns when and how types are checked/associated.
* **Strong/weak typing** → concerns the language's rules around type compatibility and conversions.

### Mistake 4: "Type hints make Python statically typed."

No. Type hints provide information for tools such as type checkers and IDEs; Python's normal runtime behavior remains dynamically typed.

---

## Interview Takeaway

A strong interview answer:

> **Dynamic typing means that Python does not require us to explicitly declare the type of a variable name, and type information is associated with objects at runtime. A name can be rebound to objects of different types during execution. For example, `x = 10` followed by `x = "Hello"` is valid Python. Dynamic typing makes Python flexible and concise, but some type-related errors are discovered only when the relevant code executes.**
