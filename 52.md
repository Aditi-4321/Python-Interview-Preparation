# Question 52 — What does `yield` do?

## Answer

The `yield` keyword is used inside a Python function to turn it into a **generator function**.

Unlike `return`, which terminates a function and returns a result, `yield`:

1. Produces a value.
2. **Pauses** the function at that point.
3. Saves the function's current state.
4. Resumes execution from the same point when the next value is requested.

### Simple definition

> **`yield` produces a value lazily and pauses the function, allowing it to continue later from where it stopped.**

---

## 1. Basic Example

```python id="5d7k2x"
def numbers():
    yield 1
    yield 2
    yield 3
```

Calling the function does **not** immediately execute the whole function:

```python id="g3v1qa"
gen = numbers()
```

`gen` is a generator object.

Now:

```python id="d8z4pl"
print(next(gen))  # 1
print(next(gen))  # 2
print(next(gen))  # 3
```

Each call to `next()` resumes the generator until it reaches the next `yield`.

---

## 2. How `yield` Pauses and Resumes Execution

Consider:

```python id="r7k2mw"
def demo():
    print("Start")
    yield 10
    print("Middle")
    yield 20
    print("End")
```

Now:

```python id="q0p6zs"
gen = demo()

print(next(gen))
print(next(gen))
print(next(gen))
```

Output:

```text id="k2j8wp"
Start
10
Middle
20
End
```

The execution happens like this:

```text
Call next()
    ↓
Print "Start"
    ↓
yield 10
    ↓
PAUSE
    ↓
Call next()
    ↓
Print "Middle"
    ↓
yield 20
    ↓
PAUSE
    ↓
Call next()
    ↓
Print "End"
    ↓
Function finishes
```

The generator remembers where it was paused.

---

## 3. `yield` vs `return`

This is one of the most important interview comparisons.

### `return`

```python id="7jj2yz"
def get_numbers():
    return [1, 2, 3]
```

The function executes and returns the complete list.

```text id="fl9k82"
Function
   ↓
Create complete list
   ↓
Return
   ↓
Function ends
```

### `yield`

```python id="2e1p4d"
def get_numbers():
    yield 1
    yield 2
    yield 3
```

Values are produced one at a time.

```text id="5k7x1c"
yield 1 → pause
yield 2 → pause
yield 3 → pause
function ends
```

### Comparison

| `return`                        | `yield`                                  |
| ------------------------------- | ---------------------------------------- |
| Returns a value                 | Produces a value                         |
| Terminates the function         | Pauses the function                      |
| Normally used once              | Can be used multiple times               |
| Does not create a generator     | Turns function into a generator function |
| Result is available immediately | Values are produced lazily               |

---

## 4. Why Is `yield` Memory Efficient?

Suppose we need numbers from 1 to 1,000,000.

Using a list:

```python id="8wq2j3"
numbers = [x for x in range(1, 1000001)]
```

The complete list is stored in memory.

Using a generator:

```python id="k4h8rp"
def numbers():
    for x in range(1, 1000001):
        yield x
```

The values are generated as needed:

```python id="z8x3vc"
for x in numbers():
    process(x)
```

The generator does not need to create and store the complete output list.

### Important

`yield` itself does not magically make every program faster. Its major advantage is **lazy evaluation**, which can reduce memory usage and allow streaming processing.

---

## 5. `yield` Preserves State

Consider:

```python id="xq5b8n"
def count():
    x = 1

    while x <= 3:
        yield x
        x += 1
```

When:

```python id="n7c4va"
gen = count()
```

is created, the function has not completed its loop.

When we call:

```python id="j6z3pu"
next(gen)
```

it produces `1` and pauses.

The value of `x` is preserved.

The next call:

```python id="2g7f1p"
next(gen)
```

continues from:

```python id="6v4x2j"
x += 1
```

and produces `2`.

This ability to preserve execution state is a key feature of generators.

---

## 6. Using `yield` with a Loop

A common pattern is:

```python id="x9j6rm"
def even_numbers(numbers):
    for number in numbers:
        if number % 2 == 0:
            yield number
```

Usage:

```python id="x7b1sa"
numbers = [1, 2, 3, 4, 5, 6]

for number in even_numbers(numbers):
    print(number)
```

Output:

```text id="y1t6wv"
2
4
6
```

Only the required values are produced during iteration.

---

## 7. `yield from`

Python also provides `yield from` for delegating iteration to another iterable or generator.

Instead of:

```python id="7ks4qg"
def numbers():
    for x in [1, 2, 3]:
        yield x
```

we can write:

```python id="q1p9ra"
def numbers():
    yield from [1, 2, 3]
```

This is particularly useful when combining generators.

Example:

```python id="0v5h6w"
def first():
    yield 1
    yield 2


def second():
    yield 3
    yield 4


def all_numbers():
    yield from first()
    yield from second()
```

Then:

```python id="7g4n9s"
print(list(all_numbers()))
```

Output:

```text id="4m5y8n"
[1, 2, 3, 4]
```

## 8. `yield` in Data and ML Pipelines

`yield` is very useful when processing large datasets.

For example, a preprocessing function can generate processed records one at a time:

```python id="q2n5sz"
def preprocess(records):
    for record in records:
        cleaned = clean(record)
        yield cleaned
```

Then:

```python id="n9x3cw"
for record in preprocess(records):
    train_model(record)
```

This supports a pipeline like:

```text id="z4x7pm"
Raw Data
   ↓
Read One Record
   ↓
Preprocess
   ↓
yield
   ↓
Train / Process
   ↓
Next Record
```

This can be useful for:

* Large datasets
* Streaming data
* Log processing
* Batch generation
* Data preprocessing
* ML data pipelines

## 9. Important Behavior: Generator Exhaustion

Once all values have been produced, the generator is exhausted.

```python id="c8v4nx"
def numbers():
    yield 1
    yield 2

gen = numbers()

print(list(gen))  # [1, 2]
print(list(gen))  # []
```

A new generator must be created for another complete iteration:

```python id="b2y7mq"
gen = numbers()
print(list(gen))  # [1, 2]
```

## Common Mistakes

### 1. Thinking `yield` returns all values

It produces values one at a time.

### 2. Thinking `yield` terminates the function

`yield` pauses the function. `return` terminates it.

### 3. Assuming generators always use less memory

Generators are often more memory-efficient because they are lazy, but the generator may still retain references to objects and the overall pipeline determines actual memory usage.

### 4. Forgetting that generator execution is lazy

```python id="n6r8yk"
def test():
    print("Hello")
    yield 10
```

This:

```python id="r3v6kt"
gen = test()
```

does not print `"Hello"`.

The function starts executing when iteration begins:

```python id="8s4kzq"
print(next(gen))
```

Output:

```text id="4m7q2p"
Hello
10
```

---

## Interview Takeaway

> **`yield` turns a normal function into a generator function. It produces a value, pauses execution, preserves the function's state, and resumes from that point when the next value is requested. This enables lazy and memory-efficient processing.**

### Easy Way to Remember

```text id="t2m6vq"
return
   ↓
Give result
   ↓
Function ends

yield
   ↓
Give value
   ↓
Pause
   ↓
Remember state
   ↓
Resume later
```

**Most important interview point:**

> **`yield` is used for lazy value generation; unlike `return`, it does not terminate the function immediately.**
