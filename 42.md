# Question 42 — Composition vs inheritance — what is the difference?

## Answer

**Composition** and **inheritance** are two different ways of designing relationships between classes in Object-Oriented Programming (OOP).

The key difference is:

> **Inheritance represents an "is-a" relationship, while composition represents a "has-a" relationship.**

For example:

```text
Inheritance:
Dog is an Animal

Composition:
Car has an Engine
```

---

## 1. Inheritance

**Inheritance** allows a child class to derive attributes and methods from a parent class.

```python id="r8v2km"
class Animal:
    def eat(self):
        print("Eating")


class Dog(Animal):
    def bark(self):
        print("Barking")


dog = Dog()

dog.eat()
dog.bark()
```

Here:

```text
Dog → Animal
```

A `Dog` **is an** `Animal`, so inheritance is a natural relationship.

### Advantages

* Promotes code reuse.
* Supports method overriding.
* Enables polymorphism.
* Represents class hierarchies naturally.

### Limitation

Inheritance can create **tight coupling** between the child and parent classes. Changes in the parent class can affect subclasses.

---

## 2. Composition

**Composition** means creating an object of one class inside another class and using that object as part of the containing class.

```python id="x5n9qt"
class Engine:
    def start(self):
        print("Engine started")


class Car:
    def __init__(self):
        self.engine = Engine()

    def start_car(self):
        self.engine.start()


car = Car()
car.start_car()
```

Here:

```text
Car → has an → Engine
```

The `Car` does not inherit from `Engine`. Instead, it **contains an `Engine` object**.

### Advantages

* Promotes flexibility.
* Reduces coupling between classes.
* Components can often be replaced independently.
* Makes it easier to change behavior by substituting different component objects.
* Often works well when behavior is assembled from independent components.

---

## Composition vs Inheritance

| Feature      | Inheritance                                | Composition                                                |
| ------------ | ------------------------------------------ | ---------------------------------------------------------- |
| Relationship | **Is-a**                                   | **Has-a**                                                  |
| Mechanism    | Child class derives from parent            | Class contains objects of other classes                    |
| Code reuse   | Through inheritance                        | Through delegation/contained objects                       |
| Coupling     | Generally tighter                          | Generally looser                                           |
| Flexibility  | Can be less flexible for changing behavior | Often more flexible                                        |
| Polymorphism | Commonly supported                         | Can also support polymorphism through component interfaces |
| Example      | `Dog` is an `Animal`                       | `Car` has an `Engine`                                      |

## A Practical Example

Suppose we are designing a notification system.

### Using inheritance

```python id="n3w7kp"
class Notification:
    def send(self):
        pass


class EmailNotification(Notification):
    def send(self):
        print("Sending email")


class SMSNotification(Notification):
    def send(self):
        print("Sending SMS")
```

Here:

```text
EmailNotification is a Notification
SMSNotification is a Notification
```

Inheritance makes sense because both are types of notifications.

---

### Using composition

Suppose an application needs to choose different notification mechanisms dynamically.

```python id="c6t2vr"
class EmailSender:
    def send(self, message):
        print("Sending email:", message)


class NotificationService:
    def __init__(self, sender):
        self.sender = sender

    def notify(self, message):
        self.sender.send(message)
```

Now we can provide different senders:

```python id="w9k4xs"
email = EmailSender()

service = NotificationService(email)

service.notify("Hello")
```

A different sender can be supplied without changing `NotificationService`.

This demonstrates why composition can provide greater flexibility when behavior needs to be replaceable.

## Composition vs Inheritance in ML

Composition is very common in machine-learning systems.

For example, a model pipeline may contain separate components:

```text
ML Pipeline
   |
   +-- Preprocessor
   |
   +-- Feature Extractor
   |
   +-- Model
   |
   +-- Evaluator
```

A pipeline can **contain** these objects instead of inheriting from them.

```python id="d4y8qm"
class Preprocessor:
    def transform(self, data):
        return data


class Model:
    def predict(self, data):
        return "prediction"


class Pipeline:
    def __init__(self, preprocessor, model):
        self.preprocessor = preprocessor
        self.model = model

    def predict(self, data):
        data = self.preprocessor.transform(data)
        return self.model.predict(data)
```

Here, `Pipeline` **has a** preprocessor and **has a** model.

This design allows different preprocessing or model implementations to be plugged into the same pipeline.

## When Should You Use Inheritance?

Use inheritance when:

* There is a genuine **"is-a"** relationship.
* The child is a specialized version of the parent.
* Subclasses share a meaningful common interface or behavior.
* Polymorphic behavior through a common base type is useful.

Example:

```text
Dog is an Animal
Car is a Vehicle
```

---

## When Should You Use Composition?

Use composition when:

* There is a **"has-a"** relationship.
* Components need to be replaceable.
* You want lower coupling.
* Behavior needs to be assembled from multiple independent components.
* Inheritance would create an artificial or overly deep class hierarchy.

Example:

```text
Car has an Engine
Computer has a CPU
ML Pipeline has a Model
```

---

## Common Mistakes

* Choosing inheritance simply because it provides code reuse.
* Using inheritance for a **"has-a"** relationship.
* Assuming composition and inheritance cannot both be used in the same application.
* Creating deep inheritance hierarchies when simpler object composition would be easier to maintain.
* Thinking composition means classes cannot interact through polymorphism. A composed object can still implement a common interface or base class.

### Interview Takeaway

> **“Inheritance represents an ‘is-a’ relationship where a child class derives from a parent class. Composition represents a ‘has-a’ relationship where a class contains and uses objects of other classes. Inheritance is useful for genuine class hierarchies, while composition often provides greater flexibility and lower coupling by allowing behavior to be assembled from replaceable components.”**
