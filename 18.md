This is an important Python interview topic because it tests whether you understand **references, mutable objects, and nested data structures**.

## Question 18 — What is the difference between shallow and deep copying?

### Answer

**Shallow copy** and **deep copy** determine how Python copies an object, especially when the object contains other mutable objects such as nested lists or dictionaries.

The key difference is:

> **Shallow copy copies the outer object but shares references to nested objects. Deep copy recursively copies the nested objects as well.**

---

### 1. Shallow Copy

A shallow copy creates a new outer object, but the elements inside it are **references to the same nested objects**.

Example:

```python id="l8tq9e"
import copy

original = [[1, 2], [3, 4]]
shallow = copy.copy(original)

shallow[0].append(5)

print(original)
print(shallow)
```

Output:

```text id="s0k8x2"
[[1, 2, 5], [3, 4]]
[[1, 2, 5], [3, 4]]
```

Why did `original` change?

Because:

```text id="7wq3p1"
original ──┐
           ├──> [1, 2]
shallow  ──┘
```

Both outer lists are different, but their first nested list is the **same object**.

You can also create a shallow copy using:

```python id="j6y1q8"
shallow = original.copy()
```

or:

```python id="1m2k9a"
shallow = original[:]
```

For a list, these create a shallow copy.

---

### 2. Deep Copy

A deep copy creates a new outer object **and recursively copies the objects contained inside it**.

```python id="h2p7c4"
import copy

original = [[1, 2], [3, 4]]
deep = copy.deepcopy(original)

deep[0].append(5)

print(original)
print(deep)
```

Output:

```text id="x6r4v9"
[[1, 2], [3, 4]]
[[1, 2, 5], [3, 4]]
```

Now the nested list is also independent:

```text id="q9m3k7"
original ──> [1, 2]

deep     ──> [1, 2, 5]
```

Therefore, modifying the nested object in `deep` does not affect `original`.

---

### 3. Visual Difference

Suppose:

```python id="h1c5z8"
original = [[10, 20], [30, 40]]
```

**Shallow copy:**

```text id="5v6s2j"
original ──> outer list ──> nested list A
                         └─> nested list B
                              ↑
copy ──────> outer list ──────┘
```

The outer lists are different, but nested lists are shared.

**Deep copy:**

```text id="8d4k1p"
original ──> outer list ──> nested list A
                         └─> nested list B

copy ──────> outer list ──> separate nested list A
                         └─> separate nested list B
```

Everything that can be copied is recursively copied according to the rules of `deepcopy`.

---

### 4. Simple Example Without `copy` Module

This is a common interview example:

```python id="y7c3m2"
a = [[1, 2], [3, 4]]
b = a.copy()

b[0][0] = 100

print(a)
print(b)
```

Output:

```text id="d5j8r2"
[[100, 2], [3, 4]]
[[100, 2], [3, 4]]
```

`a.copy()` only creates a **shallow copy**.

For an independent nested structure:

```python id="k4v9s6"
import copy

b = copy.deepcopy(a)
```

---

### 5. What About Immutable Objects?

Deep copying does not mean that Python must create a completely separate physical object for every value.

For immutable objects such as integers and strings, sharing is generally safe because they cannot be modified in place.

The important issue is **mutable nested objects** such as:

* `list`
* `dict`
* `set`
* other user-defined mutable objects

---

### 6. Why Does This Matter in Real Projects?

Suppose you have configuration data:

```python id="q2f6n1"
config = {
    "database": {
        "host": "localhost",
        "port": 3306
    }
}
```

If you create a shallow copy and modify the nested database configuration:

```python id="r7k3w5"
new_config = config.copy()

new_config["database"]["port"] = 5432
```

the original `config` also sees the changed port because the nested dictionary is shared.

If the configurations need to be completely independent:

```python id="t8p1z4"
import copy

new_config = copy.deepcopy(config)
```

Now modifying the nested dictionary does not affect the original.

---

### 7. Performance Consideration

Deep copying is more expensive than shallow copying because it may need to recursively traverse and copy a large object graph.

Therefore:

* Use **shallow copy** when sharing nested objects is intentional or safe.
* Use **deep copy** when you need an independent nested structure.
* Don't automatically use `deepcopy()` everywhere; it can consume significant time and memory for large structures.

Also, sometimes the better solution is to **construct only the independent part you actually need** rather than copying an entire large object graph.

---

### Quick Comparison

| Feature                        | Shallow Copy   | Deep Copy         |
| ------------------------------ | -------------- | ----------------- |
| New outer object               | Yes            | Yes               |
| Nested mutable objects copied? | No             | Yes, recursively  |
| Nested objects shared?         | Usually yes    | Generally no      |
| Independent nested structure?  | No             | Yes               |
| Memory usage                   | Lower          | Higher            |
| Performance                    | Usually faster | Usually slower    |
| Common method                  | `copy.copy()`  | `copy.deepcopy()` |

### Interview Takeaway

> **A shallow copy creates a new outer object but keeps references to the same nested objects. A deep copy recursively creates copies of nested objects, making the copied structure independent. Shallow copying is faster and uses less memory, while deep copying is useful when nested mutable data must not be shared.**

### Interview Follow-up

**Q: Is `list.copy()` a deep copy?**

No. `list.copy()` creates a **shallow copy**.

**Q: Why can modifying a shallow copy affect the original?**

Because both objects can reference the same nested mutable object.

**Q: When should you avoid `deepcopy()`?**

When the object is very large or when only a small part needs to be independent. Deep copying can be unnecessarily expensive in time and memory.
