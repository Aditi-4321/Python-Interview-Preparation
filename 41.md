# Question 41 — What is the difference between instance, class, and static methods?

## Answer

Python provides three commonly used types of methods inside classes:

1. **Instance methods**
2. **Class methods**
3. **Static methods**

The main difference is **what they receive as their first argument and what kind of class/instance state they can directly access**.

| Method              | Decorator       | First Parameter | Can Access Instance Data? | Can Access Class Data?          |
| ------------------- | --------------- | --------------- | ------------------------- | ------------------------------- |
| **Instance method** | None            | `self`          | Yes                       | Yes, through the class/instance |
| **Class method**    | `@classmethod`  | `cls`           | No                        | Yes                             |
| **Static method**   | `@staticmethod` | None            | No                        | No, not automatically           |

---

## 1. Instance Method

An **instance method** operates on a particular object (instance) of a class.

It takes `self` as its first parameter.

```python id="v3p7ks"
class Student:
    def __init__(self, name):
        self.name = name

    def show_name(self):
        print(self.name)


student = Student("Aditi")
student.show_name()
```

Output:

```text id="q8m2rx"
Aditi
```

Here:

```python id="z6n4wp"
self.name
```

refers to the data belonging to the particular `student` object.

### When to use?

Use an instance method when the operation needs to work with **object-specific data**.

Examples:

```text id="c2v9jt"
student.show_name()
model.predict()
account.deposit()
```

---

## 2. Class Method

A **class method** operates on the class rather than a particular instance.

It is defined using the `@classmethod` decorator and receives `cls` as its first parameter.

```python id="r4k8mn"
class Student:
    college = "MMMUT"

    @classmethod
    def show_college(cls):
        print(cls.college)


Student.show_college()
```

Output:

```text id="x1p6qd"
MMMUT
```

Here:

```python id="f7s3lw"
cls.college
```

refers to the class-level attribute.

A class method can also be called through an instance:

```python id="a9c5ye"
student = Student()
student.show_college()
```

but it still receives the **class** as `cls`, not the instance as `self`.

### Common Use: Alternative Constructors

Class methods are often useful for creating objects in different ways.

```python id="m8q2vk"
class Student:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    @classmethod
    def from_string(cls, data):
        name, age = data.split(",")
        return cls(name, int(age))


student = Student.from_string("Aditi,22")

print(student.name)
print(student.age)
```

Here `from_string()` acts as an **alternative constructor**.

Using `cls` instead of directly writing `Student` also allows the method to work correctly with subclasses.

### When to use?

Use a class method when the operation:

* Works with **class-level state**
* Needs access to `cls`
* Acts as an **alternative constructor**
* Should be designed to support subclasses

---

## 3. Static Method

A **static method** does not automatically receive either the instance (`self`) or the class (`cls`).

It is defined using `@staticmethod`.

```python id="t6w1pz"
class Calculator:

    @staticmethod
    def add(a, b):
        return a + b


print(Calculator.add(10, 20))
```

Output:

```text id="n3j7xc"
30
```

The method does not need any information from a particular object or the class.

### When to use?

Use a static method when a function:

* Logically belongs to the class
* Does not need instance data
* Does not need class data

For example:

```python id="b5r9qn"
class MathUtils:

    @staticmethod
    def is_even(n):
        return n % 2 == 0


print(MathUtils.is_even(10))
```

The function is related to `MathUtils`, but it does not need an instance or class state.

## Complete Comparison Example

```python id="p3k7vz"
class Student:
    college = "MMMUT"

    def __init__(self, name):
        self.name = name

    # Instance method
    def show_name(self):
        print(self.name)

    # Class method
    @classmethod
    def show_college(cls):
        print(cls.college)

    # Static method
    @staticmethod
    def is_adult(age):
        return age >= 18


student = Student("Aditi")

student.show_name()
Student.show_college()
print(Student.is_adult(22))
```

Output:

```text id="r2x8mc"
Aditi
MMMUT
True
```

### What happens internally?

```text id="h7q4ns"
Instance method
      ↓
    self
      ↓
Specific object/instance data

Class method
      ↓
     cls
      ↓
Class-level data

Static method
      ↓
No automatic self/cls
      ↓
Independent utility logic
```

---

## Important Difference: `self` vs `cls`

### `self`

Refers to the **current instance**.

```python
self.name
```

Different objects can have different values.

### `cls`

Refers to the **class itself**.

```python
cls.college
```

The value is associated with the class.

## ML Example

These method types can also appear in ML-oriented classes.

```python id="u4m8ps"
class Model:

    def __init__(self, name):
        self.name = name

    # Instance method
    def predict(self, data):
        print(f"Prediction using {self.name}")

    # Class method
    @classmethod
    def default_model(cls):
        return cls("Default Model")

    # Static method
    @staticmethod
    def validate_data(data):
        return len(data) > 0
```

Here:

* `predict()` needs information about a particular model instance.
* `default_model()` creates a model using class-level construction logic.
* `validate_data()` is a utility operation that does not require model or class state.

## Common Mistakes

* Forgetting that instance methods receive `self` automatically when called through an instance.
* Assuming `cls` represents an instance. It represents the **class**.
* Using `@staticmethod` when the method actually needs instance or class state.
* Confusing a class method with an alternative constructor. Alternative constructors are a **common use** of class methods, not their only purpose.
* Thinking static methods are completely unrelated to the class. They are still defined in the class namespace and are often used for logically related utility operations.

## Interview Follow-up

**1. Why do instance methods use `self`?**
`self` provides access to the current object's attributes and other instance methods.

**2. Why do class methods use `cls`?**
`cls` provides access to the class itself, including class attributes and class-level behavior.

**3. When should you use a static method instead of an instance method?**
Use a static method when the operation does not require instance-specific or class-specific state but logically belongs to the class.

### Interview Takeaway

> **“An instance method works with a specific object and receives `self`. A class method works with the class and receives `cls`, and is commonly used for class-level operations or alternative constructors. A static method does not automatically receive either `self` or `cls` and is useful for utility logic related to the class.”**
