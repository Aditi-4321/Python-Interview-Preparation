## Question 20 — What is a set and how does it work conceptually?

### Answer

A **set** is an **unordered collection of unique, hashable elements** in Python.

Sets are mainly used when we need to:

* Remove duplicate values.
* Perform fast membership testing.
* Perform mathematical set operations such as union, intersection, and difference.

A set is created using `{}` with elements:

```python id="q3f7k2"
numbers = {10, 20, 30, 20, 10}

print(numbers)
```

Output will contain each value only once:

```text id="j8m4p1"
{10, 20, 30}
```

The exact display order should not be relied upon.

> **Important:** `{}` by itself creates an empty dictionary, not an empty set. Use `set()` for an empty set.

```python id="v6c2r9"
empty_set = set()
empty_dict = {}
```

---

### 1. How Does a Set Work Conceptually?

Conceptually, Python sets are implemented using a **hash table**.

When you add an element:

```python id="a9n5t4"
numbers.add(50)
```

Python calculates a **hash value** for the element and uses it to determine where to store/find the element in the underlying hash-table structure.

For example, conceptually:

```text id="r2k8w6"
Element
   ↓
hash(element)
   ↓
Hash table location
   ↓
Store / find element
```

When checking:

```python id="z5p3x7"
50 in numbers
```

Python uses the element's hash to locate the relevant area rather than normally scanning every element one by one.

This is why set membership testing is typically **O(1) average time**.

---

### 2. Why Must Set Elements Be Hashable?

Set elements need a stable hash value so Python can efficiently locate them.

Therefore, immutable/hashable objects such as:

```python id="f7m2q8"
numbers = {10, 20, 30}
names = {"Aditi", "Rahul"}
```

can be stored in a set.

But a list cannot:

```python id="n4v8s1"
my_set = {[1, 2], [3, 4]}
```

This raises:

```text id="x6c9p2"
TypeError: unhashable type: 'list'
```

A tuple containing only hashable elements can generally be used:

```python id="w3k7d5"
points = {(10, 20), (30, 40)}
```

But:

```python id="b8q2m6"
data = {([1, 2], 3)}
```

is not valid because the tuple contains an unhashable list.

---

### 3. Sets Automatically Remove Duplicates

This is one of the most common uses:

```python id="s9v4k2"
numbers = [1, 2, 2, 3, 3, 3, 4]

unique_numbers = set(numbers)

print(unique_numbers)
```

The result contains only unique values.

If you need a list again:

```python id="e2f8n7"
unique_numbers = list(set(numbers))
```

However, this approach should **not** be used when the original order must be preserved.

---

### 4. Fast Membership Testing

Suppose we need to repeatedly check whether a value exists.

```python id="p5m1x8"
allowed = {"admin", "editor", "user"}

role = "editor"

if role in allowed:
    print("Access allowed")
```

Set membership is typically **O(1) average time**.

Compare this with a list:

```python id="h7r3c9"
allowed = ["admin", "editor", "user"]

if role in allowed:
    print("Access allowed")
```

List membership is generally **O(n)** because Python may have to check elements one by one.

For large collections with frequent membership checks, a set can therefore be a much better data structure.

---

### 5. Mathematical Set Operations

Python provides operations corresponding to mathematical sets.

#### Union

Elements present in either set:

```python id="d8v5q2"
a = {1, 2, 3}
b = {3, 4, 5}

print(a | b)
```

Result:

```text id="n2k6s4"
{1, 2, 3, 4, 5}
```

Equivalent method:

```python id="g5x8m1"
a.union(b)
```

#### Intersection

Elements common to both:

```python id="c7r4p9"
print(a & b)
```

Result:

```text id="u6m3z8"
{3}
```

#### Difference

Elements present in `a` but not in `b`:

```python id="j9q2v5"
print(a - b)
```

Result:

```text id="t4h7k1"
{1, 2}
```

#### Symmetric Difference

Elements present in either set but not both:

```python id="f3w8n6"
print(a ^ b)
```

Result:

```text id="y5c1r9"
{1, 2, 4, 5}
```

---

### 6. Important Properties

A Python set is:

* **Unique** → duplicate elements are automatically eliminated.
* **Unordered** → don't use it when you need sequence-style positional order.
* **Mutable** → elements can be added or removed.
* **Hash-based** → elements must be hashable.
* **Not indexable** → `my_set[0]` is not supported.

For example:

```python id="k8n2s5"
numbers = {10, 20, 30}

# numbers[0]   # TypeError
```

If positional access is required, a list is generally more appropriate.

---

### 7. Set vs List

| Feature                    | Set                                  | List               |
| -------------------------- | ------------------------------------ | ------------------ |
| Duplicate elements         | No                                   | Yes                |
| Positional indexing        | No                                   | Yes                |
| Membership testing         | O(1) average                         | O(n)               |
| Ordered sequence semantics | No                                   | Yes                |
| Mutable                    | Yes                                  | Yes                |
| Elements                   | Must be hashable                     | Can be any objects |
| Main use                   | Uniqueness/membership/set operations | Ordered collection |

---

### 8. Practical Example

Suppose two courses have enrolled students:

```python id="r6m9t3"
java_students = {"Aditi", "Rahul", "Neha"}
python_students = {"Neha", "Aman", "Aditi"}

both = java_students & python_students
only_java = java_students - python_students

print("Both courses:", both)
print("Only Java:", only_java)
```

This is much clearer than manually comparing two lists.

---

### Interview Takeaway

> **A set is a mutable collection of unique, hashable elements. Conceptually, it uses a hash-table structure, allowing average O(1) membership checks, insertion, and deletion. Sets are especially useful for removing duplicates, fast membership testing, and operations such as union, intersection, and difference.**

### Interview Follow-up

**Q: Why can't a list be stored in a set?**

Because lists are mutable and therefore unhashable.

**Q: Is a set ordered?**

You should treat a set as having no positional ordering; don't rely on its iteration/display order for program logic.

**Q: What is the average complexity of `x in my_set`?**

Approximately **O(1)** average time, although worst-case hash-table behavior can degrade.

**Q: What is the difference between `{}` and `set()`?**

```python
{}       # empty dictionary
set()    # empty set
```
