# Question 77 — Write code to identify duplicates efficiently.

## Answer

The most efficient general approach is to use a **set** because set membership checking takes **O(1) average time**.

```python
def find_duplicates(arr):
    seen = set()
    duplicates = set()

    for x in arr:
        if x in seen:
            duplicates.add(x)
        else:
            seen.add(x)

    return list(duplicates)


arr = [1, 2, 3, 2, 4, 5, 1, 3, 6]

print(find_duplicates(arr))
```

### Output

```text
[1, 2, 3]
```

### How it works

* `seen` stores elements encountered for the first time.
* If an element is already in `seen`, it is a duplicate.
* `duplicates` stores duplicate values.
* Using a set prevents the same duplicate from being added repeatedly.

### Complexity

For `n` elements:

* **Time:** O(n) average
* **Space:** O(n)

This is more efficient than a nested-loop approach, which takes **O(n²)** time.

### If we only need to check whether duplicates exist

```python
def has_duplicates(arr):
    seen = set()

    for x in arr:
        if x in seen:
            return True
        seen.add(x)

    return False


arr = [1, 2, 3, 4, 2]

print(has_duplicates(arr))
```

**Output:**

```text
True
```

This version can stop immediately when the first duplicate is found.

### Common Mistake

Using nested loops is simple but inefficient for large inputs:

```python
for i in range(len(arr)):
    for j in range(i + 1, len(arr)):
        if arr[i] == arr[j]:
            print(arr[i])
```

Its time complexity is **O(n²)**.

### Interview Follow-up

**Why is a set used here?**

A set provides average **O(1)** membership checking, allowing us to scan the list once and identify duplicates in **O(n)** average time.

### Interview Takeaway

> Use a **set** for efficient duplicate detection: maintain a `seen` set, scan the elements once, and record elements that appear again.
