# Question 59 — What are pip, requirements.txt, and dependency management?

## Answer

These three concepts are closely related:

> **`pip` installs Python packages, `requirements.txt` records project dependencies, and dependency management is the overall process of controlling, installing, updating, and reproducing those dependencies safely.**

---

# 1. What is `pip`?

**pip** is Python's standard package installer and is commonly used to install and manage packages from the Python Package Index (**PyPI**) and other package indexes.

For example:

```bash
python -m pip install pandas
```

This installs the `pandas` package into the active Python environment.

You can then use it:

```python
import pandas as pd
```

### Common `pip` commands

#### Install a package

```bash
python -m pip install numpy
```

#### Install a specific version

```bash
python -m pip install numpy==2.0.0
```

#### Upgrade a package

```bash
python -m pip install --upgrade numpy
```

#### Uninstall a package

```bash
python -m pip uninstall numpy
```

#### Show installed packages

```bash
python -m pip list
```

#### Show information about a package

```bash
python -m pip show numpy
```

#### Check for outdated packages

```bash
python -m pip list --outdated
```

Using:

```bash
python -m pip
```

is often preferable to simply:

```bash
pip
```

because it makes clear which Python interpreter's `pip` you are using.

---

# 2. What is PyPI?

**PyPI** stands for **Python Package Index**.

It is a public repository containing a large number of Python packages.

For example, packages such as:

```text
NumPy
Pandas
Requests
Flask
scikit-learn
```

are available through PyPI.

When you run:

```bash
python -m pip install pandas
```

pip normally obtains the package from a configured package index, commonly PyPI.

Conceptually:

```text
Your Project
     ↓
    pip
     ↓
Package Index
     ↓
Download package
     ↓
Install into Python environment
```

---

# 3. What is a Dependency?

A **dependency** is an external software component that your project requires to work correctly.

For example:

```python
import pandas
import numpy
```

means your project depends on Pandas and NumPy.

An ML project might have dependencies such as:

```text
numpy
pandas
scikit-learn
matplotlib
```

Some packages can themselves depend on other packages.

For example:

```text
Your ML application
       ↓
   scikit-learn
       ↓
     NumPy
       ↓
     SciPy
```

These are called **transitive dependencies** when they are required indirectly through another dependency.

---

# 4. What is `requirements.txt`?

`requirements.txt` is a plain text file commonly used to specify Python dependencies required by a project.

Example:

```text
numpy==2.0.0
pandas==2.2.2
scikit-learn==1.5.1
matplotlib==3.9.2
```

Each line specifies a package requirement.

This file allows another developer or deployment environment to install the project's dependencies.

For example:

```bash
python -m pip install -r requirements.txt
```

The `-r` option tells pip to read the requirements from the file.

---

# 5. Why is `requirements.txt` Important?

Imagine you create an ML project and send only:

```text
main.py
model.py
data.py
```

Another developer may not know:

* Which packages are required.
* Which versions were tested.
* Which dependencies need to be installed.

With:

```text
requirements.txt
```

the project documents its Python dependencies.

For example:

```text
project/
│
├── main.py
├── model.py
├── requirements.txt
└── README.md
```

Another developer can run:

```bash
python -m pip install -r requirements.txt
```

and install the specified requirements.

---

# 6. How to Generate `requirements.txt`

If your virtual environment already contains the packages your project uses, you can run:

```bash
python -m pip freeze > requirements.txt
```

For example, it may produce:

```text
numpy==2.x.x
pandas==2.x.x
scikit-learn==1.x.x
```

The exact versions depend on your environment.

Then commit the file to Git:

```bash
git add requirements.txt
git commit -m "Add project dependencies"
git push
```

This is useful for sharing the project.

---

# 7. `pip freeze` vs Manually Writing Requirements

There is an important practical distinction.

### `pip freeze`

```bash
python -m pip freeze > requirements.txt
```

records packages installed in the current environment, including packages that may not be direct dependencies of your application.

For example, your environment might contain:

```text
numpy
pandas
scikit-learn
pytest
jupyter
```

even if the application only directly requires:

```text
numpy
pandas
scikit-learn
```

Therefore, `pip freeze` is convenient for capturing an environment, but it is not always an ideal representation of the project's direct dependency specification.

For larger or longer-lived projects, teams may use more structured dependency-management tools and lock files.

---

# 8. Dependency Management

**Dependency management** means controlling the external packages and versions that a project requires throughout its lifecycle.

It includes:

1. Identifying dependencies.
2. Installing them.
3. Controlling compatible versions.
4. Resolving dependency conflicts.
5. Updating dependencies.
6. Reproducing environments.
7. Tracking security vulnerabilities.
8. Testing after upgrades.

For example:

```text
Project
  ↓
Dependencies
  ↓
Versions
  ↓
Environment
  ↓
Testing
  ↓
Deployment
```

---

# 9. Why Dependency Versions Matter

Suppose your code was developed with:

```text
Library A → version 1.x
```

and later someone installs:

```text
Library A → version 2.x
```

The API may have changed.

For example:

```text
Old API
   ↓
works

New API
   ↓
function removed/changed
   ↓
application fails
```

This is why projects often specify version constraints.

For example:

```text
pandas==2.2.2
```

means:

> Use exactly version `2.2.2`.

Other forms are also possible:

```text
pandas>=2.0
```

means version 2.0 or newer.

```text
pandas>=2.0,<3.0
```

means a compatible version within that range.

The exact constraint should be chosen based on the project's compatibility and testing requirements.

---

# 10. Exact Pinning vs Version Ranges

### Exact version

```text
numpy==2.0.0
```

Advantages:

* More reproducible.
* Reduces unexpected upgrades.

Disadvantages:

* Can make upgrades slower.
* Requires deliberate maintenance.

### Version range

```text
numpy>=2.0,<3.0
```

Advantages:

* Allows compatible updates.
* Provides more flexibility.

Disadvantages:

* A newly released version within the range could still introduce behavior your project has not been tested against.

In production, teams often combine version constraints with a lock/fully resolved dependency set and automated testing.

---

# 11. Dependency Conflicts

A common real-world problem is:

```text
Your application
     ↓
Package A → requires dependency X < 2
Package B → requires dependency X >= 2
```

Now the requirements conflict.

This can result in installation failures or an environment that cannot satisfy all requirements simultaneously.

Dependency managers/resolvers attempt to find a set of package versions that satisfies the declared constraints.

This is one reason dependency management becomes increasingly important as a project grows.

---

# 12. Virtual Environment + pip + requirements.txt

These concepts work together.

Suppose you start a new ML project.

### Step 1 — Create environment

```bash
python -m venv .venv
```

### Step 2 — Activate it

Windows:

```powershell
.venv\Scripts\Activate.ps1
```

### Step 3 — Install dependencies

```bash
python -m pip install numpy pandas scikit-learn
```

### Step 4 — Save environment information

```bash
python -m pip freeze > requirements.txt
```

### Step 5 — Share project

```text
project/
├── .venv/              ← don't normally commit
├── main.py
├── requirements.txt    ← commit
├── README.md
└── .gitignore
```

### Step 6 — Another developer recreates it

```bash
python -m venv .venv
```

Activate it:

```bash
.venv\Scripts\Activate.ps1
```

Then:

```bash
python -m pip install -r requirements.txt
```

This creates a separate environment containing the specified dependencies.

---

# 13. `pip` Does Not Create the Virtual Environment

This is a common interview confusion.

### `venv`

Creates the isolated Python environment:

```bash
python -m venv .venv
```

### `pip`

Installs and manages packages inside that environment:

```bash
python -m pip install pandas
```

### `requirements.txt`

Records dependency requirements:

```text
pandas==...
numpy==...
```

So:

```text
venv → creates environment
pip → installs/manages packages
requirements.txt → describes dependencies
```

# 14. Dependency Management in an AI/ML Project

Consider an ML application:

```text
AI/ML Project
│
├── NumPy
├── Pandas
├── Scikit-learn
├── Matplotlib
├── PyTorch
└── Transformers
```

The project may have dozens or even hundreds of transitive dependencies.

A production workflow might look like:

```text
Define dependencies
       ↓
Create isolated environment
       ↓
Install/resolution
       ↓
Run tests
       ↓
Train/test model
       ↓
Build deployment artifact
       ↓
Monitor
       ↓
Update dependencies deliberately
```

This helps avoid the situation where a library upgrade unexpectedly changes model-training or inference behavior.

For ML projects, dependency versions can also affect:

* Numerical results
* Model serialization compatibility
* Preprocessing behavior
* GPU/CUDA compatibility
* Inference performance
* Reproducibility

---

# 15. Security and Dependency Management

Dependency management is also a **security concern**.

Third-party packages can contain vulnerabilities.

Therefore, production teams should:

* Keep dependencies reasonably up to date.
* Monitor known vulnerabilities.
* Remove unused dependencies.
* Review dependency changes.
* Use trusted package sources.
* Test upgrades before deployment.
* Pin or constrain versions appropriately.
* Use automated dependency/security scanning where appropriate.

Dependency management is therefore not just about "making imports work."

---

# 16. `requirements.txt` vs Modern Dependency Tools

`requirements.txt` remains common and useful, especially for straightforward projects.

However, larger Python projects may use tools such as:

* **Poetry**
* **uv**
* **pip-tools**
* **Conda** in some data-science environments

These tools can provide stronger dependency resolution, project metadata, lock files, or environment management.

For example, a modern project may maintain:

```text
pyproject.toml
```

as its project/dependency configuration.

The important interview concept is not memorizing every tool, but understanding:

> **Direct dependencies should be declared clearly, compatible versions should be resolved, and the resulting environment should be reproducible and tested.**

# 17. Practical Debugging

If you encounter:

```text
ModuleNotFoundError: No module named 'pandas'
```

check:

### 1. Is the correct environment active?

```bash
python -c "import sys; print(sys.executable)"
```

### 2. Is the package installed in that environment?

```bash
python -m pip show pandas
```

### 3. Install it if necessary

```bash
python -m pip install pandas
```

### 4. If the project provides requirements

```bash
python -m pip install -r requirements.txt
```

### 5. Check the actual imported package

```python
import pandas

print(pandas.__file__)
```

This helps identify cases where multiple Python environments are involved.

## Common Mistakes

### 1. Confusing `pip` with PyPI

* **PyPI** → package repository/index.
* **pip** → tool used to install/manage packages.

### 2. Thinking `requirements.txt` installs packages

It doesn't install anything by itself.

This command does:

```bash
python -m pip install -r requirements.txt
```

### 3. Using the wrong Python environment

Always check:

```bash
python -c "import sys; print(sys.executable)"
```

### 4. Blindly updating every dependency

A package upgrade can introduce breaking changes or change ML behavior.

Test dependency upgrades before using them in production.

### 5. Committing `.venv`

Usually commit:

```text
requirements.txt
```

not:

```text
.venv/
```

---

## Interview Takeaway

> **pip is Python's package installation and management tool, requirements.txt is a common file for declaring project dependencies and their version constraints, and dependency management is the broader practice of installing, resolving, updating, securing, and reproducing those dependencies. Together with virtual environments, they help prevent conflicts and make Python projects reproducible and maintainable.**

### Interview Follow-up

**Q: What is the difference between pip and PyPI?**
PyPI is a package repository/index, while pip is a tool that installs and manages packages from PyPI or other configured indexes.

**Q: What is the difference between `pip freeze` and `requirements.txt`?**
`pip freeze` is a command that outputs the installed packages and versions in an environment. `requirements.txt` is a file used to specify dependency requirements. `pip freeze > requirements.txt` is one common way to generate such a file.

**Q: Why use a virtual environment with `requirements.txt`?**
The virtual environment isolates the project's packages, while `requirements.txt` records what dependencies should be installed, making it easier to recreate the environment.

**Q: Why can dependency management be especially important in ML?**
Different library versions can affect preprocessing, numerical behavior, model serialization, training, inference, and hardware compatibility, so controlled and tested dependencies improve reproducibility.
