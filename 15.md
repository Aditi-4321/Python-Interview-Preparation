This is an important **DSA + Python interview** question because interviewers often ask not just what a list operation does, but **why one operation is faster than another**.

## Question 15 — What are the time complexities of common list operations?

### Answer

Python's `list` is implemented as a **dynamic array** in the standard CPython implementation. This means elements are stored in an array-like structure, which gives **O(1) average-time random access**, but inserting or deleting elements in the middle can require shifting other elements.

Let `n` be the number of elements in the list.

### Common List Operations

| Operation           | Example          |                   Time Complexity | Why?                                   |
| ------------------- | ---------------- | --------------------------------: | -------------------------------------- |
| Access by index     | `a[i]`           |                          **O(1)** | Direct index calculation               |
| Update by index     | `a[i] = x`       |                          **O(1)** | Direct access                          |
| Append at end       | `a.append(x)`    |                **O(1) amortized** | Usually adds at the next free position |
| Pop from end        | `a.pop()`        |                          **O(1)** | Removes last element                   |
| Insert at beginning | `a.insert(0, x)` |                          **O(n)** | Existing elements must shift           |
| Insert in middle    | `a.insert(i, x)` |                          **O(n)** | Elements may need to shift             |
| Delete by index     | `a.pop(i)`       |                          **O(n)** | Elements after `i` may shift           |
| Remove by value     | `a.remove(x)`    |                          **O(n)** | May need to search first               |
| Search              | `x in a`         |                          **O(n)** | Linear search                          |
| Find index          | `a.index(x)`     |                          **O(n)** | Linear search                          |
| Slice               | `a[i:j]`         |                          **O(k)** | Creates a new list of `k` elements     |
| Concatenation       | `a + b`          |                      **O(n + m)** | Creates a new list                     |
| Sort                | `a.sort()`       | **O(n log n)** average/worst-case | Uses Timsort                           |
| Reverse in-place    | `a.reverse()`    |                          **O(n)** | Visits the elements                    |
| Copy                | `a.copy()`       |                          **O(n)** | Copies references                      |

Here, `k` is the number of elements in the resulting slice, and `m` is the size of the second list.

---

### 1. Access — O(1)

```python id="f1x2p4"
numbers = [10, 20, 30, 40, 50]

print(numbers[3])
```

Output:

```text
40
```

Python can directly calculate where index `3` is located, so it does not need to examine elements `0`, `1`, and `2`.

Therefore:

**Time = O(1)**

This is one of the major advantages of arrays/lists.

---

### 2. Append — O(1) Amortized

```python id="wq3f9k"
numbers.append(60)
```

Appending normally places the new element at the end.

Therefore, the **amortized complexity is O(1)**.

Why "amortized"?

A dynamic array occasionally needs to allocate a larger underlying storage area and copy existing elements. That individual resize can take **O(n)**, but it does not happen on every append.

Across a long sequence of appends, the average cost per append is **O(1) amortized**.

---

### 3. Insert — O(n)

```python id="7v8q2c"
numbers.insert(0, 5)
```

If we insert at the beginning, existing elements need to move:

```text
Before:
[10, 20, 30, 40]

After:
[5, 10, 20, 30, 40]
```

Several elements have to be shifted.

Therefore:

**Time = O(n)**

The same reasoning applies to insertion in the middle.

---

### 4. Pop from the End — O(1)

```python id="j2r5xm"
numbers.pop()
```

Only the last element needs to be removed.

Therefore:

**Time = O(1)**

But:

```python id="7y4d1b"
numbers.pop(0)
```

is **O(n)** because the remaining elements need to shift left.

---

### 5. Search — O(n)

For:

```python id="3w0g8v"
if 50 in numbers:
    print("Found")
```

Python may have to examine every element.

For example, if the desired value is at the last position:

```text
10 → 20 → 30 → 40 → 50
                         ↑
                      found
```

Therefore:

**Time = O(n)** in the worst case.

---

### 6. Remove by Value — O(n)

```python id="m8j3q1"
numbers.remove(30)
```

Python first has to find `30`, which can take O(n), and then may need to shift subsequent elements.

Therefore the overall complexity is:

**O(n)**

---

### 7. Slicing — O(k)

Consider:

```python id="n6h4s2"
part = numbers[2:5]
```

Slicing creates a **new list** containing the selected elements.

If `k` elements are copied:

**Time = O(k)**

It also requires **O(k) additional memory**.

This is important when working with very large lists.

---

### 8. Sorting — O(n log n)

```python id="q4e8v7"
numbers.sort()
```

Python's list sorting uses **Timsort**.

For typical complexity analysis, sorting is:

**O(n log n)**

It is an efficient comparison-based sorting algorithm and can take advantage of existing order in the data.

---

### 9. Important Comparison: List vs Set

Suppose you frequently need to check whether an item exists.

With a list:

```python id="p7f1s6"
if item in my_list:
    ...
```

Average/worst-case search is generally:

**O(n)**

A set is usually more appropriate for frequent membership testing:

```python id="j6m2r8"
if item in my_set:
    ...
```

Average-case membership testing is approximately:

**O(1)**

This illustrates an important engineering principle:

> **Choose the data structure based on the operations you perform most frequently.**

---

### Interview Example

If an interviewer asks:

> "Why is `list.append()` O(1) but `list.insert(0, x)` O(n)?"

A strong answer is:

> "Python lists are dynamic arrays. Appending at the end usually places the element in the next available position, so it is O(1) amortized. Inserting at the beginning requires shifting existing elements to make space, so it takes O(n)."

### Interview Takeaway

The most important complexities to remember are:

```text
Access by index       → O(1)
Append                → O(1) amortized
Pop from end          → O(1)
Search                → O(n)
Remove by value       → O(n)
Insert at beginning   → O(n)
Pop from beginning    → O(n)
Sort                  → O(n log n)
```

The key reason is that **Python lists are dynamic arrays**: random access is fast, but operations that require shifting many elements are linear.
