## Question 3 — What are variables and objects in Python?

### Answer

In Python, it is important to understand that **variables are names/references, while objects are the actual entities that hold data and have a type and identity**.

For example:

```python
age = 21
```

Here:

* `age` → variable (more precisely, a **name**)
* `21` → object
* `int` → type of the object

A useful mental model is:

```text
age ─────────► 21
              object
```

Python variables do not directly contain the value in the same way that a simple variable model might suggest. A name **refers to an object**.

---

## 1. What is an Object?

An **object** is a runtime entity in Python that has:

1. **Identity** — identifies the particular object
2. **Type** — determines what kind of object it is and what operations it supports
3. **Value/state** — the data contained by the object

For example:

```python
name = "Aditi"
```

`"Aditi"` is a string object.

We can inspect its properties:

```python
name = "Aditi"

print(type(name))
print(id(name))
```

Possible output:

```text
<class 'str'>
140735...
```

The exact value returned by `id()` is implementation-dependent.

### Important point

**Everything in Python is an object**, including:

* integers
* strings
* lists
* dictionaries
* functions
* classes
* modules

For example:

```python
x = 10
print(type(x))       # <class 'int'>

numbers = [1, 2, 3]
print(type(numbers)) # <class 'list'>
```

---

## 2. What is a Variable?

In Python, a variable is better understood as a **name bound to an object**.

```python
x = 10
```

Conceptually:

```text
x ───────► 10
          int object
```

The name `x` refers to the integer object `10`.

Python does not require you to declare the variable's type explicitly:

```python
x = 10
x = "Hello"
x = [1, 2, 3]
```

The same name can refer to objects of different types at different times.

This is one reason Python is called **dynamically typed**.

---

## 3. Variables Can Refer to the Same Object

Consider:

```python
a = [1, 2, 3]
b = a
```

Now:

```text
a ───────┐
         ├──► [1, 2, 3]
b ───────┘
```

Both names refer to the **same list object**.

Therefore:

```python
b.append(4)

print(a)
```

Output:

```text
[1, 2, 3, 4]
```

Why?

Because `a` and `b` refer to the same mutable object.

---

## 4. Assignment Does Not Normally Copy the Object

This is a common interview point.

```python
a = [10, 20]
b = a
```

This does **not** create a second list.

It creates another reference to the existing list.

If you actually want a separate shallow copy:

```python
b = a.copy()
```

Now:

```text
a ───► [10, 20]

b ───► [10, 20]
```

They contain the same values initially, but they are different list objects.

---

## 5. Mutable vs Immutable Objects

Objects in Python can be **mutable** or **immutable**.

### Mutable objects

Their contents can be changed after creation.

Examples:

```text
list
dict
set
```

Example:

```python
numbers = [1, 2, 3]
numbers.append(4)

print(numbers)
```

Output:

```text
[1, 2, 3, 4]
```

The existing list was modified.

### Immutable objects

Their value cannot be changed after the object is created.

Common examples include:

```text
int
float
str
tuple
bool
```

For example:

```python
x = 10
x = x + 5
```

This does not modify the integer object `10`.

Instead, the expression produces another integer object representing `15`, and the name `x` is rebound to that object.

Conceptually:

```text
Before:

x ───► 10

After:

x ───► 15
```

## 6. `is` vs `==`

Understanding variables and objects also helps explain the difference between `==` and `is`.

### `==`

Checks whether two objects have **equal values** according to their equality operation.

```python
a = [1, 2]
b = [1, 2]

print(a == b)
```

Output:

```text
True
```

### `is`

Checks whether two references refer to the **same object**.

```python
print(a is b)
```

Output:

```text
False
```

because `a` and `b` refer to different list objects.

A useful rule:

> Use `==` when you want to compare values; use `is` when you specifically need to check object identity.

A common special case is:

```python
if value is None:
    ...
```

## Practical Example

Suppose we have:

```python
student1 = ["Aditi", 21]
student2 = student1

student2[1] = 22

print(student1)
```

Output:

```text
['Aditi', 22]
```

### Why?

Because:

```text
student1 ──────┐
               ├──► ["Aditi", 21]
student2 ──────┘
```

Both names point to the same mutable list.

After changing the list through `student2`, `student1` sees the same change.

## Common Mistakes

### 1. Saying "a variable stores the value"

This is an acceptable beginner-level simplification, but technically Python names **refer to objects**.

### 2. Assuming assignment creates a copy

```python
b = a
```

usually creates another reference, not a copy.

### 3. Confusing `is` and `==`

```python
a == b  # value/equality comparison
a is b  # identity comparison
```

### 4. Thinking immutable means the variable cannot change

This is incorrect.

```python
x = 10
x = 20
```

The **name** `x` can be rebound. What is immutable is the integer object itself.

---

## Interview Takeaway

Remember this model:

```text
Variable/Name ─────► Object
                       │
                 ┌─────┴─────┐
                 │            │
               Type         Value
                 │
              Identity
```

A strong interview answer is:

> **In Python, a variable is more accurately a name that refers to an object. An object is a runtime entity that has an identity, type, and value. Python is dynamically typed, so a name can refer to objects of different types during execution. Assignment generally creates another reference to an existing object rather than copying it. Understanding this relationship is especially important when working with mutable objects such as lists and dictionaries.**
