# Question 30 — What is variable scope in Python?

## Answer

**Variable scope** refers to the region of a Python program where a variable can be **accessed or referenced**.

In simple words:

> **Scope determines where a variable is visible and where Python can find it.**

Python mainly follows the **LEGB rule** to determine where a name should be searched:

```text
L → Local
E → Enclosing
G → Global
B → Built-in
```

---

## 1. Local Scope

A variable created **inside a function** normally has local scope. It can be accessed only within that function.

```python id="0qf3mp"
def calculate():
    x = 10
    print(x)

calculate()
```

Here, `x` is a local variable.

Trying to access it outside the function:

```python id="k4e8bx"
print(x)
```

causes a `NameError` because `x` is not defined in the current scope.

### Why?

Local variables are generally created for the function's execution and are not directly accessible from outside that function.

---

## 2. Global Scope

A variable defined at the **module/program level**, outside functions, has global scope within that module.

```python id="k0h9lv"
x = 10

def show():
    print(x)

show()
print(x)
```

Both accesses can read the global `x`.

However, assigning to `x` inside a function creates a **local variable** by default rather than modifying the global variable.

```python id="l7l1xw"
x = 10

def change():
    x = 20
    print(x)

change()
print(x)
```

Output:

```text id="7v4b9q"
20
10
```

The `x` inside `change()` is a different local name.

---

## 3. `global` Keyword

If a function needs to **assign to a global variable**, we can explicitly use the `global` keyword.

```python id="x3z5jd"
x = 10

def change():
    global x
    x = 20

change()
print(x)
```

Output:

```text id="q4q3i1"
20
```

Here, `global x` tells Python that the assignment should refer to the module-level `x`.

### Practical note

Although `global` is valid, excessive use of global mutable state can make programs harder to test, understand, and maintain. Passing values through function parameters and return values is usually clearer.

---

# 4. Enclosing Scope

An **enclosing scope** occurs when a function is defined inside another function.

```python id="v3c6sl"
def outer():
    x = 10

    def inner():
        print(x)

    inner()

outer()
```

Here:

```text id="2d8y3r"
outer()
 └── x = 10
      └── inner() can access x
```

`x` belongs to the enclosing function's scope from the perspective of `inner()`.

---

## `nonlocal` Keyword

If an inner function needs to **modify** a variable from its enclosing function, we use `nonlocal`.

```python id="q9g2r1"
def counter():
    count = 0

    def increment():
        nonlocal count
        count += 1
        return count

    return increment

c = counter()

print(c())
print(c())
```

Output:

```text id="yq3t7h"
1
2
```

`nonlocal count` tells Python to use the `count` from the enclosing `counter()` function rather than creating a new local `count`.

This concept is important for understanding **closures**.

---

# 5. Built-in Scope

Python also has a built-in namespace containing names such as:

```python
len()
print()
sum()
max()
min()
type()
```

For example:

```python id="e5xj0m"
numbers = [10, 20, 30]

print(len(numbers))
```

Python searches for `len` according to its name-resolution rules and ultimately finds the built-in `len()` function.

---

# LEGB Rule

When Python encounters a name, it generally searches scopes in this order:

```text id="j8d0q6"
L → Local
E → Enclosing
G → Global
B → Built-in
```

Example:

```python id="m4jv1w"
x = "global"

def outer():
    x = "enclosing"

    def inner():
        x = "local"
        print(x)

    inner()

outer()
```

Output:

```text id="k4p9qy"
local
```

Python finds the nearest `x`, which is the local one.

If the local `x` were removed, Python would search the enclosing scope, then global, and finally built-ins.

---

# Scope vs Lifetime

Scope and lifetime are related but **not the same thing**.

* **Scope** → where a name can be accessed.
* **Lifetime** → how long the referenced object exists.

For example:

```python id="8g7c2x"
def test():
    x = [1, 2, 3]
    return x
```

The local name `x` is only accessible inside `test()`. However, the list object can continue to exist after the function returns because the returned value still references it.

---

# Scope in AI/ML Code

Understanding scope is important in ML programs because models, datasets, configuration values, and intermediate results are often handled across multiple functions.

For example:

```python id="b2u6c8"
def train_model(X, y):
    model = "trained model"
    return model

model = train_model(X_train, y_train)
```

Here, `model` inside `train_model()` is local to that function, while the returned value is assigned to a different `model` name outside the function.

Using function parameters and return values makes ML pipelines easier to test and reduces unintended dependencies between different parts of the code.

---

## Common Mistakes

### 1. Assuming a function can modify a global variable automatically

```python id="x8g2s1"
x = 10

def change():
    x = 20
```

This does **not** change the global `x`.

### 2. Using `global` unnecessarily

Global state can make code harder to debug and maintain. Prefer parameters and return values when practical.

### 3. Confusing scope with object lifetime

A local variable name may disappear after a function returns, while the object it referenced can remain alive if another reference exists.

---

## Interview Takeaway

> **Variable scope defines where a name can be accessed in a Python program. Python uses the LEGB rule—Local, Enclosing, Global, and Built-in—to resolve names. The `global` keyword allows assignment to a global variable, while `nonlocal` allows an inner function to modify a variable from its enclosing scope.**

### Interview Follow-up

**Q: What is LEGB in Python?**
LEGB stands for **Local, Enclosing, Global, and Built-in**, the order Python follows when resolving names.

**Q: What is the difference between `global` and `nonlocal`?**

| Keyword    | Refers to                           |
| ---------- | ----------------------------------- |
| `global`   | A module/global variable            |
| `nonlocal` | A variable in an enclosing function |

**Q: Can an inner function access a variable from its outer function?**
Yes. This is possible because of the enclosing scope and is an important concept behind **closures**.
