## Question 19 — What is a tuple and when would you use it?

### Answer

A **tuple** is an ordered, immutable collection of objects in Python. It is similar to a list, but once a tuple is created, its elements cannot be changed, added, or removed.

Tuples are usually written using parentheses `()`:

```python id="9z6b2m"
student = ("Aditi", 22, "MCA")
```

A tuple can contain different data types:

```python id="7j3x8c"
data = ("Aditi", 22, 85.5, True)
```

---

### 1. Why is a Tuple Immutable?

Once created:

```python id="c2q8n5"
point = (10, 20)

point[0] = 50
```

Python raises:

```text id="p4m7s1"
TypeError: 'tuple' object does not support item assignment
```

Unlike a list:

```python id="w8r2k6"
point = [10, 20]
point[0] = 50

print(point)
```

Output:

```text id="d1v9c3"
[50, 20]
```

So the basic distinction is:

```text id="q6t3a8"
List   → mutable
Tuple  → immutable
```

---

### 2. When Would You Use a Tuple?

#### a. When the data should not change

For fixed values, a tuple communicates that the collection is intended to remain unchanged.

```python id="u5k8r1"
rgb = (255, 128, 0)
```

This could represent a fixed RGB color.

Another example:

```python id="z3p7m4"
coordinates = (26.8467, 80.9462)
```

A tuple is appropriate when the two values together represent a fixed coordinate pair.

---

#### b. Returning multiple values from a function

Python functions can return multiple values using a tuple:

```python id="f6n2q9"
def get_student():
    return "Aditi", 22

name, age = get_student()

print(name)
print(age)
```

Output:

```text id="m8c1v5"
Aditi
22
```

This is a very common Python pattern.

---

#### c. Using it as a dictionary key

A tuple containing only hashable elements can be used as a dictionary key:

```python id="r4k7x2"
locations = {
    (26.8467, 80.9462): "Lucknow"
}
```

A list cannot be used as a dictionary key because lists are mutable and unhashable.

This is useful for representing composite keys such as:

```python id="h3q9v6"
scores = {
    ("Aditi", "Java"): 95,
    ("Aditi", "Python"): 90
}
```

---

#### d. Unpacking structured data

Tuples work naturally with unpacking:

```python id="b7m2k4"
student = ("Aditi", 22, "MCA")

name, age, course = student

print(name)
print(age)
print(course)
```

This makes code concise and readable when the number and meaning of values are known.

---

#### e. Representing fixed records

A tuple can represent a small, fixed group of related values:

```python id="c8v5n1"
employee = ("Aditi", "Software Engineer", 75000)
```

For more complex records, however, a class, `dataclass`, or another structured representation may be clearer.

---

### 3. Tuple vs List

| Feature             | Tuple                             | List                |
| ------------------- | --------------------------------- | ------------------- |
| Ordered             | Yes                               | Yes                 |
| Mutable             | No                                | Yes                 |
| Syntax              | `(1, 2, 3)`                       | `[1, 2, 3]`         |
| Add/remove elements | No                                | Yes                 |
| Dictionary key      | Yes, if all elements are hashable | No                  |
| Typical use         | Fixed data                        | Changing collection |

---

### 4. Important Tuple Detail

A tuple is immutable, but it can contain a mutable object:

```python id="n6t2y8"
data = ([1, 2], 10)

data[0].append(3)

print(data)
```

Output:

```text id="s5r9c2"
([1, 2, 3], 10)
```

The tuple itself was not changed—the list **inside** the tuple was modified.

This is a common interview trick.

---

### 5. Single-Element Tuple

A single-element tuple requires a comma:

```python id="k9f3w7"
a = (10,)
b = (10)

print(type(a))
print(type(b))
```

Output:

```text id="v4n8q1"
<class 'tuple'>
<class 'int'>
```

The comma is what makes `a` a tuple.

---

### 6. Performance and Memory

Tuples can have lower memory overhead than lists for a fixed collection because tuples do not need to support list-style mutation operations.

However, don't choose a tuple merely because it may be slightly more memory-efficient. The **main reason to use a tuple is semantic**: the collection represents fixed or immutable data.

### Interview Takeaway

> **A tuple is an ordered and immutable collection. I would use it when the data should remain fixed, when returning multiple values from a function, for unpacking structured values, or when a hashable composite key is needed. If the collection needs to be modified, I would generally use a list instead.**

### Interview Follow-up

**Q: Can a tuple contain a list?**

Yes. The tuple remains immutable, but the nested list can still be modified.

**Q: Can every tuple be a dictionary key?**

No. A tuple is hashable only when all of its elements are hashable.

**Q: Why use a tuple instead of a list for fixed data?**

It communicates that the collection itself should not be modified and can also be used as a dictionary key when hashable.
