# Question 51 — What is the difference between an iterator and a generator?

## Answer

Both **iterators** and **generators** are used to produce values **one at a time**, which makes them useful for lazy and memory-efficient processing.

The main difference is:

> **An iterator is an object that follows Python's iterator protocol, while a generator is a convenient way to create an iterator using `yield` or a generator expression.**

In other words:

```text
Iterator
→ General concept/protocol

Generator
→ A specific, convenient type of iterator
```

---

## 1. Iterator

An iterator is an object that implements:

* `__iter__()`
* `__next__()`

Example:

```python
class Count:
    def __init__(self, limit):
        self.current = 1
        self.limit = limit

    def __iter__(self):
        return self

    def __next__(self):
        if self.current <= self.limit:
            value = self.current
            self.current += 1
            return value

        raise StopIteration


it = Count(3)

print(next(it))  # 1
print(next(it))  # 2
print(next(it))  # 3
```

Here, we manually manage:

* Current state
* `__iter__()`
* `__next__()`
* `StopIteration`

---

## 2. Generator

A generator is a simpler way to create an iterator using the `yield` keyword.

```python
def count(limit):
    current = 1

    while current <= limit:
        yield current
        current += 1


gen = count(3)

print(next(gen))  # 1
print(next(gen))  # 2
print(next(gen))  # 3
```

Python automatically manages the iterator state for us.

The `yield` statement:

1. Produces a value.
2. Pauses the function.
3. Remembers its current state.
4. Resumes from that point when `next()` is called again.

---

## 3. Key Difference

| Iterator                                                      | Generator                                              |
| ------------------------------------------------------------- | ------------------------------------------------------ |
| General iterator protocol                                     | Specific type of iterator                              |
| Usually created by implementing `__iter__()` and `__next__()` | Usually created using `yield` or generator expressions |
| State management may need to be written manually              | Python automatically manages state                     |
| Can be implemented as a class                                 | Usually implemented as a function                      |
| More code for simple sequences                                | Usually much shorter and simpler                       |
| Useful when custom iteration behavior is required             | Excellent for simple lazy sequences and pipelines      |

---

## 4. Generator is an Iterator

This is an important interview point.

```python
def numbers():
    yield 1
    yield 2
    yield 3


gen = numbers()

print(iter(gen) is gen)
```

Output:

```text
True
```

A generator provides both `__iter__()` and `__next__()`, so it is an iterator.

Therefore:

> **Every generator is an iterator, but every iterator is not a generator.**

---

## 5. `yield` vs `return`

A common source of confusion is the difference between `yield` and `return`.

### `return`

```python
def numbers():
    return [1, 2, 3]
```

The function returns the complete list at once.

### `yield`

```python
def numbers():
    yield 1
    yield 2
    yield 3
```

The function produces values one at a time.

The generator pauses at each `yield` and resumes from there when requested.

---

## 6. Memory Efficiency

Generators are useful when processing large amounts of data because they can produce values lazily.

### List

```python
numbers = [x * 2 for x in range(1000000)]
```

The complete list is created and stored in memory.

### Generator

```python
numbers = (x * 2 for x in range(1000000))
```

Values are produced as needed.

```python
print(next(numbers))
print(next(numbers))
```

This can significantly reduce memory usage when the complete sequence does not need to exist simultaneously.

### Important clarification

Generators are not automatically faster in every situation. Their main advantage is **lazy evaluation and potentially lower memory usage**, especially for large or streaming data.

---

## 7. Generator Expression

A generator can also be created using a generator expression:

```python
numbers = (x * 2 for x in range(5))

for number in numbers:
    print(number)
```

Compare this with a list comprehension:

```python
numbers = [x * 2 for x in range(5)]
```

The list comprehension creates the complete list, while the generator expression produces values lazily.

---

## 8. State Management

With a custom iterator, we explicitly maintain state:

```python
self.current += 1
```

With a generator:

```python
def count():
    current = 1

    while current <= 3:
        yield current
        current += 1
```

Python automatically preserves the function's execution state between calls to `next()`.

Conceptually:

```text
Generator starts
      ↓
yield value
      ↓
pause
      ↓
next()
      ↓
resume
      ↓
yield next value
```

This is one of the biggest reasons generators are convenient.

---

## 9. When Would You Use Each?

### Use a generator when:

* You need simple lazy processing.
* Data is large.
* Data should be processed one item at a time.
* You are building a data-processing pipeline.
* You want concise iterator code.

Example:

```python
def read_numbers(file):
    for line in file:
        yield int(line.strip())
```

### Use a custom iterator when:

* You need complex iteration behavior.
* You need a dedicated iterator class.
* You need to maintain multiple pieces of custom state.
* The iteration logic belongs naturally to an object.
* You need behavior that is easier to express through a class.

## 10. ML/Data Processing Example

Suppose a dataset contains millions of records.

Instead of loading and processing everything at once:

```python
data = load_all_data()
process(data)
```

we can use a generator:

```python
def process_records(records):
    for record in records:
        if valid(record):
            yield preprocess(record)
```

Then:

```python
for record in process_records(records):
    train_model(record)
```

The records can be processed incrementally.

This pattern is useful for:

* Large datasets
* Data preprocessing
* Streaming pipelines
* Batch generation
* Log processing
* ML training data pipelines

## Common Mistakes

### 1. Saying generators and iterators are completely different concepts

A generator **is an iterator**.

The difference is mainly in how the iterator is created and how its state is managed.

### 2. Saying generators always use less memory

Generators are generally memory-efficient because they produce values lazily, but actual memory usage depends on what the generator retains and what the surrounding program does.

### 3. Thinking `yield` returns all values

`yield` produces one value and pauses execution. The next value is produced when iteration resumes.

### 4. Forgetting that generators are usually single-use

```python
gen = (x for x in range(3))

print(list(gen))  # [0, 1, 2]
print(list(gen))  # []
```

Once exhausted, the generator cannot normally be restarted. Create a new generator if another traversal is required.

## Interview Takeaway

> **An iterator is any object that follows Python's iterator protocol by providing `__iter__()` and `__next__()`. A generator is a special kind of iterator created conveniently using `yield` or a generator expression. Generators automatically preserve execution state and are particularly useful for lazy, memory-efficient processing.**

### Easy Way to Remember

```text
Iterator
    ↓
General mechanism for producing values one by one

Generator
    ↓
Convenient way to create an iterator
    ↓
Uses yield
    ↓
Lazy + automatic state management
```

**Most important interview statement:**

> **Every generator is an iterator, but every iterator is not a generator.**
